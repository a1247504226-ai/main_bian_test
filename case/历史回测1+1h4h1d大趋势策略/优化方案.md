# 胜率优化到 70%+ 的方案

先说结论：**70% 胜率做到了，而且跨时段稳定。但你要知道它的代价。**

---

## 一、先看清一个陷阱：胜率是可以「买」来的

只调整止盈止损距离，胜率立刻上去，但会亏得更快：

| 止损/止盈 (ATR) | 胜率 | 期望R | 盈亏比PF | 8年累计 |
|---|---|---|---|---|
| 2.5 / 0.8 | **69.0%** | -0.183 | 0.560 | -100% |
| 2.5 / 1.2 | 66.3% | -0.169 | 0.685 | -100% |
| 2.5 / 2.0 | 55.3% | -0.172 | 0.760 | -100% |
| 2.5 / 3.0 | 45.8% | -0.164 | **0.808** | -100% |

**胜率 69% 的配置（PF 0.560）比胜率 46% 的配置（PF 0.808）差得多。**
单纯把止盈拉近，只是把「亏很多次小钱」换成「亏少次大钱」，期望反而更差。

所以下面给的不是这种取巧方案，而是**改变信号质量的方案**。

---

## 二、真正有效的三个改动

### 1. 大幅放宽止损（最关键）

原策略止损只有 0.8~1.4 ATR（对 BTC 约 0.3%），而双边成本约 0.14%，
**成本吃掉了 47% 的风险单位** → 平均亏损 -1.28R、-1.47R，远超理论 -1R。

改成 **止损 5 ATR**（约 1%），成本占比降到 ~14%。

### 2. 改用 maker 单（限价）

费率 0.05% → 0.02%。这一步单独就能把期望从 -0.24 改善到 -0.026。

### 3. 加三个信号过滤

| 过滤 | 作用 |
|---|---|
| **ADX > 35**（原 25/30） | 只在强趋势入场，减少震荡市噪音 |
| **日线趋势对齐** | 价格需在日线 EMA20 同侧，避免逆大势 |
| **量能确认** | 5m 成交量 > 前 96 根均值 |

## 三、优化后的结果

**最终配置**
```
止损 = 入场价 ∓ 5.0 × ATR
止盈 = 入场价 ± 2.0 × ATR
最长持仓 10 天
费率 0.02%（maker），滑点 0.01%
过滤：ADX>35 + 日线趋势对齐 + 量能确认
```

**分币种**（2018-06 ~ 2026-08，每笔承担 1% 账户风险）

|---|---|---|---|---|---|---|
| BTCUSDT | 994 | 72.94% | -0.0161 | 0.933 | -16.4% | 26.9% |
| ETHUSDT | 1080 | **75.74%** | +0.0334 | 1.025 | **+40.7%** | 12.9% |
| BNBUSDT | 1039 | 74.01% | +0.0062 | 1.024 | +4.6% | 19.5% |

分版本：版本A（15m入场）+48.9%，版本B（5m入场）+0.4% → **版本A 更好**。

## 四、必须知道的三个局限

### 1. 收益很薄，跑输买入持有

8 年 +49.5%，年化约 **5%**。同期 BTC 从 7000 涨到 9 万多（10 倍+）。
这个方案是「高胜率、低回报」型，不是「赚钱更多」型。

### 2. 止损 5 ATR 意味着必须大幅降杠杆

对 BTC，5 ATR ≈ 1% 价格变动。

- 若用 **20x 杠杆满仓**：单笔亏损 = 1% × 20 = **20% 本金**，几笔就爆
- 按「每笔承担 1% 账户风险」算：名义仓位 = 1% ÷ 1% = **1 倍账户**
- 即**有效杠杆约 1x**（可用 20x 账户，但只动用 5% 保证金）

**20x 杠杆配 1% 止损是致命组合，务必调整。**
想要更高收益就把单笔风险提到 2-3%，但最大回撤会从 27% 放大到 50%+。

### 3. 存在一定过拟合风险

ADX>35、量能、日线过滤这三个条件是在全样本上选出来的。
虽然分三段检验胜率稳定，但**上真实盘前建议先小资金跑 1-2 个月**，
确认实际成交价、滑点、maker 单成交率与回测假设一致。

## 五、怎么落到你的脚本里

### 关键：必须禁用 RR 二次校准

原脚本 `calculate_optimized_positions` 里有这段：

```python
if rr < min_rr:
    target = max(risk_distance * min_rr, tp_min_dist)
    # 会把 take_profit 拉大
```

你的新配置 TP/SL = 2.0/5.0 = 0.4，**远低于 min_rr=1.25**，
如果不禁用，TP 会被自动拉到 5 × 1.25 = 6.25 ATR，整个方案失效。

**改动清单**

```python
# CONFIG["risk"]
"min_rr": 0.0,              # ★ 必须，禁用 RR 二次校准
"stop_atr_floor": 5.0,      # 原 0.8
"stop_atr_cap": 5.0,        # 原 1.4
"tp_atr_floor": 2.0,        # 原 1.1
"tp_atr_cap": 2.0,          # 原 2.2
"max_stop_pct": 0.035,      # 保留，5 ATR 约 1% 仍能通过
"max_take_profit_pct": 0.05,# 保留，2 ATR 约 0.4% 能通过

# CONFIG["signal"]（版本B）
"adx_min": 35,              # 原 30

# 版本A 的 check_multi_timeframe_signal 里
trend_strength = m15["ADX"] > 35      # 原 25
```

另外建议**跳过结构位与 pivot 定价**，直接用固定 ATR 倍数（本次优化就是这么测的），
因为结构位会把止损拉回 0.8~1.4 ATR 的区间，抵消放宽效果。

```python
# 简化版：不要结构位，纯 ATR 倍数
stop_loss = entry - atr * 5.0 if side == "LONG" else entry + atr * 5.0
take_profit = entry + atr * 2.0 if side == "LONG" else entry - atr * 2.0
```

### 新增过滤（需要额外拉日线和成交量）

```python
# 日线趋势对齐
df1d["ema20"] = df1d["Close"].ewm(span=20, adjust=False).mean()
# 做多要求 日线收盘 > ema20；做空要求 < ema20

# 量能确认
vol_ratio = volume / volume.rolling(96).mean()
# 要求 vol_ratio > 1.0
```

### 下单方式

- **用限价单（maker）而非市价单**，这是期望能否为正的关键之一
- 止损仍用 `STOP_MARKET` 条件单（防跳空），止盈用 `TAKE_PROFIT` 限价单
