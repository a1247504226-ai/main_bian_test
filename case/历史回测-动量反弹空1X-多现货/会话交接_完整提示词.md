## 3. 策略唯一口径（不许改，除非用户明确要求）

### 3.1 信号
- **双均线 EMA 10 / 30**：EMA10 > EMA30 → 做多信号；EMA10 < EMA30 → 做空信号。
- **收盘确认，次日开盘成交**（无前视）。
- **SMA50 只约束多头**：收盘价 < SMA50 时不开多（信号记为 0 = 空仓），**空头照做**。
- `sig=0`（金叉但价在 SMA50 下方）时**不做空** —— 实测做空是过拟合。

### 3.2 仓位
```
名义 = 权益 × min(exposure_cap, vt / 当日波动率)
当日波动率 = ATR(14) / 收盘价
```
- `vt = 0.06`（波动率目标 6%/日），`exposure_cap = 2.0`
- **进场那天定名义，持仓期间不再调仓**（`resize_on_drift = false`）
- 杠杆只决定保证金占用与爆仓线，**不改变名义仓位**；但 `leverage` 必须 ≥ `exposure_cap`，
  否则保证金不够、敞口开不出去。

### 3.3 载体
- **双腿都走合约 2× 全仓**（`long_leg = "fut"`，`margin_type = "CROSSED"`）。
- **没有现货腿**：账户里不持有现货 BTC，程序也不再查询现货账户。
- 为什么不用现货多头：敞口上限 >1 时现货买不到超过权益的量。
  代价是多头要付资金费（约 −4%/年），这是「2 倍仓位」的强制成本。

### 3.4 止损
- **空头：逆行 5% 市价买回**（`short_stop = 0.05`），`stop_reentry = "immediate"`
  （下一根按信号立即重进）。
- **多头：不设止损**（靠 2× 的 −50% 爆仓线保护；历史最深逆行 −25%，余 25pp）。
- 条件单必须走 **Algo Order 接口**（`/fapi/v1/algoOrder` + `algoType=CONDITIONAL`），
  旧接口会返回 `-4120`。详见第 7 节 K 类。
- 杠杆 **不能超过 3×**（4× 多头爆仓线 −25% 正好会被打到）。

### 3.5 成本口径
- 合约 Taker **0.05%/边**（VIP0，不假设 BNB 抵扣）
- 现货 0.10%/边（仅旧方案用）
- 资金费 **0.03%/日**（8 小时一次 × 3）
- 滑点 0.05%/边

### 3.6 账户口径
- `base_capital_usdt = 1000`，从**用户实际参与的那一笔**起算。
- `participate_from_next_trade = true`：当前这笔不参与，下一次仓位变化起自动计入。
- 每笔名义 = 当时账户权益 × 敞口；`my_pnl = 引擎pnl × (我的权益 / 引擎入场时权益)`，链式累加。
- ⚠️ 滚仓链必须补合约开仓费（`_p -= e_ref × expo × FUT_FEE`，仅 `leg=="fut"`）。

## 7. 已修 bug 清单（52 个，按类别）

### A. 下单正确性（15）
1. 平空方向写死 `BUY` → 合约多头时被币安 `-2022` 拒单；改为按持仓方向取 `BUY/SELL`。
2. 开空数量未按 `max_notional` 截断 → 可能超出可用保证金。
3. 未先按 `stepSize` 取整就判断 → 精度拒单。
4. **下单锁只在 `execute(lock=True)`**，`--live` 直调绕过 → 双倍仓位。
5. 开空划转按未取整量算 → 多划 48 U。
6. 合约市价单 `newOrderRespType` 默认 ACK → `executedQty` 全 0；改 `RESULT`。
7. `snapshot()` 未计入合约 `totalWalletBalance` → 权益算少。
8. 现货 / 合约 USDT 是独立账户，未显式划转 → 余额不足。
9. 行情滞后 >3 天仍允许下单。
10. **`btc_trade.py` 曾完全没有价格/滞后闸门**（只有 `btc_monitor` 有）→ 直接跑 bat 可绕过；
    现在偏离 30 日均价 5 倍 → rc=4，滞后 >3 天 → rc=5。
11. 权益为 0 时返回 `ok=True` → 现在直接 `False`。
12. 无动作/失败时 `trade_state.json` 不落盘 → `--status` 误报「很久没跑」。
13. `release_lock` 无条件删锁 → 僵尸锁接管后互删 → 并发双开；现在只删自己 pid 的锁。
14. 止损条件单非幂等 → `sync_stop_order()` 改成 `closePosition=true` + `workingType=MARK_PRICE`。
15. `auto_stop_order=false` 时用户手动按邮件旧成本价挂止损 → 加仓后成本加权会挂错（实测 9.2% vs 5%）。

19. **浮点残值 `-1e-17` 让「有持仓」成立** → 取整成 0 → 每轮跳过 → **仓位永久卡死**；
    现在 `abs(have_fut) < step×0.5` 一律当 0。
20. 划转金额 `%.8f` 四舍五入 → 超过实际可用被拒；改 `floor` 向下取整。
21. 划转金额三处（日志 / 预演余额 / 实际划转）不一致 → 统一在生成动作时取整。

### G. 止盈止损 / 改单（7，本次修复）
> 策略**只有止损、没有止盈**（移动止盈实测更差，已否决）。所以这里审的是

34. **挂止损失败被吞成成功**：`_sync_stop` 捕获异常后只打日志，`_execute` 仍返回

40. **`--status` 看不到真实挂单**：只显示理论止损价，手动挂错/改单失败都发现不了。

### H. 失败告警邮件（3，本次新增）
41. **失败不再只是控制台一行字**：`btc_trade.py` 新增 `send_trade_alert()`，

    - 止损价被击穿、已市价平仓（warn 级，不是失败但要让人知道）

### J. 平仓路径（2，本次修复）
48. **平仓被 `-2022 ReduceOnly Order is rejected` 误报失败**：快照之后仓位可能
    已经被止损单打掉（或手动平了），这时 reduceOnly 单必然被拒 —— 但目标状态
    其实已经达成。现在会**重读一次仓位**：确实为 0 → 视为已平仓成功；
    仓位还在（方向搞反/快照过期）→ 仍然报失败并要求人工核对。
49. **撤止损单时 `-2011 Unknown order sent` 误报失败**：订单可能已被手动撤掉或
    已触发，撤单必然报「不存在」。现在把 `-2011/-2013` 视为「已经撤掉了」，不算失败。

> **平仓路径已用 20 个仿真断言覆盖**：正常平空/平多、反手、`-2022` 两种分支、
> 部分成交补齐、精度不足报失败、`-2011` 撤单、多空不双开、幂等。

### K. 币安条件单迁移到 Algo Order（1 个致命 + 1 个显示，2026-11-17 实盘发现）
> ⚠️ **这条是最重要的**：2025-12-09 起币安把 USDⓈ-M 条件单强制迁到 Algo Service。
50. **止损单根本挂不上（`-4120`）**。真实测试网实测：
    ```

    -4120 Order type not supported for this endpoint.
          Please use the Algo Order API endpoints instead.
    ```
    后果：**仓位开着但完全没有止损保护**，而且旧代码只在日志里报错（现在会发告警邮件）。
    已改：
    - 挂单 → `POST /fapi/v1/algoOrder`，必须带 `algoType=CONDITIONAL`，

    - 查询 → `GET /fapi/v1/openAlgoOrders`，与 `openOrders` 合并；
      字段归一化：`algoId→orderId`、`triggerPrice→stopPrice`、`orderType→type`
    - 撤单 → `DELETE /fapi/v1/algoOrder` + `algoId`
    - 老环境（`-404`/`-1102`/Path invalid）自动回退旧接口
    - 算法单带 `_algo=True` 标记，撤单时据此选对端点
51. **成交均价显示 `0.00`**：测试网 `newOrderRespType=RESULT` 返回的 `avgPrice` 是 0，
    日志写成「成交 0.1096 @ 0.00」，看着像没成交。现在「均价为 0」也会补查一次
    `orderStatus`；仍拿不到就写「交易所未返回均价」，不再显示 0.00。

52. **全仓模式 `--status` 显示「保证金 0.00」**：`positionRisk.isolatedMargin` 在全仓下
    恒为 0，和同屏「占用保证金 ≈ 3508 U」自相矛盾。展示口径改为 `名义 ÷ 杠杆`；
    `build_actions()` 里 `released` 的计算口径保持不变（那里要区分是否已含浮盈）。

> **判断标准**：跑完 `--status`，看到「已挂止损单 #xxxx 触发价 xxxxx」才算真的挂上了。
> 只看到「开仓成功」不算成功 —— 没有止损的仓位比没开仓更危险。

## 10. 环境坑（踩过的，务必遵守）

1. **CRLF**：本项目的 `.py` / `.md` 必须是 CRLF；`.bat` 必须 **CRLF + 纯 ASCII**。
   Edit 工具默认写 LF，改完要检查并转回 CRLF。
2. **Bash 删目录**：`rm -rf "$VAR/子目录"` 会被 safe-delete 静默跳过 → 先 `cd` 再删，或删完 `ls` 确认。
3. **追加文本**：`cat >> 文件 <<'EOF'` 会被拒 → 用 Edit。
4. **代理**：行情域名 `data-api.binance.vision` 不需代理；交易域名本机不通。
   **能收邮件 ≠ 能下单**，须在 `binance.proxy` 填 `http://127.0.0.1:7890`。
5. **POST 绝不自动重试**（除 `-1021` 时间戳错误）；GET 重试 3 次。
6. **同步**：改完必须 `cp` 到交付目录，并 `diff -rq` 校验；清运行产物
   （`monitor_log.txt` / `monitor_state.json` / `trade_*` / `exchange_rules.json` / `__pycache__`）。
