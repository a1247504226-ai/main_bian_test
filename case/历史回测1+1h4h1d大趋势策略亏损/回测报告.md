# 两个多周期策略回测报告

生成时间：2026-09-29
回测区间：**2017-08-17 ~ 2026-08-31**（约 9 年）
标的：BTCUSDT / ETHUSDT / BNBUSDT / SOLUSDT（现货，5m 基础数据）

---

## 一、先回答"正确率"

| 策略 | 对应脚本 | 交易笔数 | **胜率(止盈命中)** | 多头胜率 | 空头胜率 | 6h方向正确率 |
|---|---|---|---|---|---|---|
| 版本A（4h+1h 定方向，15m 金叉入场） | `binance_multi_tf_monitor_optimized.py` | 6362 | **42.06%** | 42.0% | 42.2% | 44.3% |
| 版本B（4h+1h+15m 三层趋势，5m 金叉入场） | `binance_multi_tf_monitor_5m_entry_optimized.py` | 5621 | **41.59%** | 42.0% | 41.4% | 44.6% |

**但胜率不是最有意义的数字。** 这两个策略每笔固定承担 1% 风险，8 年下来累计亏损 **-99% 以上**，属于确定性亏损策略。

分币种（版本A / 版本B）：

| 标的 | 笔数 | 胜率 | 平均R | 盈亏比PF |
|---|---|---|---|---|
| BTCUSDT | 1567 / 1373 | 42.2% / 41.2% | -0.307 / -0.520 | 0.67 / 0.51 |
| ETHUSDT | 1611 / 1456 | 43.2% / 44.0% | -0.200 / -0.314 | 0.74 / 0.70 |
| BNBUSDT | 1803 / 1561 | 41.3% / 41.6% | -0.271 / -0.412 | 0.70 / 0.61 |
| SOLUSDT | 1381 / 1231 | 41.6% / 39.1% | -0.180 / -0.336 | 0.74 / 0.56 |

四个币种、9 年、近 1.2 万笔交易，结论高度一致，**不是样本巧合**。

---

## 二、为什么会亏：三个诊断

### 诊断 1：成本是主因，但策略本身也没有 edge

把费率从 0 逐步加到现货 taker 费率（BTC+ETH 样本）：

| 单边费率 | 版本A 期望R | 版本A PF | 版本B 期望R | 版本B PF |
|---|---|---|---|---|
| **0（理论）** | **-0.013** | **0.958** | **-0.008** | **0.990** |
| 0.02%（maker） | -0.082 | 0.878 | -0.123 | 0.863 |
| 0.05%（合约 taker） | -0.183 | 0.771 | -0.293 | 0.703 |
| 0.10%（现货 taker） | -0.348 | 0.621 | -0.557 | 0.498 |

两条关键读数：

1. **即使零成本，PF 也只有 0.96~0.99** —— 意味着策略本身几乎没有正向期望，只是"勉强打平略亏"。
2. 成本把 -0.01R 放大到 -0.18R（合约）甚至 -0.35R（现货）。**约 95% 的亏损来自交易成本。**

成本之所以杀伤这么大，是因为策略**止损太近、持仓太短**：

- 版本A 平均持仓 1.5 小时，版本B 只有 **0.4 小时**
- 止损距离约为 ATR 的 0.8~1.4 倍（对 BTC 约 0.3%）
- 双边成本 0.14%（手续费 0.1% + 滑点 0.04%）≈ 止损距离的 **47%**
- 结果：平均亏损达 **-1.28R / -1.47R**，远超理论的 -1R

### 诊断 2：信号有轻微"反向"倾向

把信号完全反转后重跑（BTC）：

| | 原版 | 反向 |
|---|---|---|
| 6小时方向正确率 | 41.5% | **59.1%** |
| 止盈命中率 | 42.2% | 33.3% |
| 期望 R | -0.303 | -0.381 |

方向正确率反转后反而升到 59%，说明信号确实带**追涨杀跌**属性——在 4h+1h 都已确认趋势、15m 刚金叉时入场，往往是短期动能耗尽的时点。

但注意：反向后止盈命中率反而更低、期望更差。因为止盈止损是非对称的（TP 距离 > SL 距离），单纯反转信号并不能直接变成盈利策略。**这说明"方向正确率"和"能不能赚钱"是两件事，不能只看前者。**

### 诊断 3：调参救不回来

| 调整方向 | 结果 |
|---|---|
| 放宽止损（ATR 0.8-1.4 → 1.6-2.6） | 交易数从 3178 骤降到 177（被 max_stop_pct 3.5% 过滤），期望仍 -0.25R |
| 提高趋势门槛（ADX 22/32 → 35/50） | 几乎无变化，期望 -0.25R |
| 提高最小盈亏比（1.25 → 1.6） | 交易数降到 168，期望 -0.10R，仍为负 |
| 提高最小盈亏比（→ 2.0） | 交易数仅 31 笔，统计无意义 |

**没有任何参数组合能把期望转正。** 放宽止损和提高 RR 只能减缓亏损速度，不能改变方向。

---

## 三、结论

1. **两个策略在 9 年、4 个币种、约 1.2 万笔交易上都是负期望**，胜率 41-43%，盈亏比 0.5-0.74，最大回撤接近 100%。
2. 亏损的**直接原因是交易成本**（占 95%），**根本原因是不存在可交易 edge**（零成本 PF ≈ 0.97）。
3. 参数微调无法修复——这不是参数问题，是信号结构问题。

## 四、如果要继续用，建议按这个优先级改

| 优先级 | 改动 | 预期效果 |
|---|---|---|
| P0 | **改市价单为限价单（maker）** | 费率 0.05% → 0.02%，亏损速度降低约 60%，这是唯一立竿见影的 |
| P0 | **加最小持仓时间过滤**（如 30 分钟内不开第二单） | 当前平均持仓仅 0.4 小时，大量交易是噪音 |
| P1 | **放宽止损到 ATR 1.6-2.6 倍**，同时放宽 max_stop_pct 到 6-8% | 降低单位风险的成本占比（否则放宽后会被 3.5% 上限全过滤掉） |
| P1 | **加入日线趋势过滤**，只在日线方向与信号同向时入场 | 减少逆大势的追涨杀跌 |
| P2 | **研究反向版本** | 方向正确率 59% 是有价值的线索，但需要重新设计非对称的出场规则 |
| P2 | 加入成交量确认、避免在低波动时段（ADX 刚上穿时）入场 | 提高信号质量 |

## 五、回测口径说明（可信度依据）

数据源为币安官方批量数据包 `data.binance.vision`，非 REST 分页。

防未来函数处理：

1. 高周期（4h/1h/15m/日线）指标按 `close_time` **向后对齐**，只取信号时刻已收盘的那根
2. 结构位窗口使用 `rolling(n).shift(1)`，**不含信号 bar 本身**
3. 成交价取信号 bar 收盘后**第一个 5m bar 的开盘价**，不是信号 bar 的收盘价
4. 出场判定从成交 bar 开始，同一根 5m 同时触及 TP 与 SL 时**保守判为 SL**
5. 完整复刻了原脚本的风控过滤：`max_stop_pct=3.5%`、`max_take_profit_pct=5%`、`min_rr=1.25`、30 分钟信号冷却
6. 指标实现（RSI/MACD/KDJ/ATR/ADX）与线上脚本逐行一致，包括 `ewm(alpha=1/period)`、`ewm(com=2)` 等细节

已知近似：

- 用现货价格回测合约策略（永续锚定现货，差异在基差，对短周期结论影响有限）
- TP/SL 判定基于 5m 的 high/low，未使用更细粒度（1m）数据，实际触发时点可能有偏差
- 滑点按固定 0.02% 估计，未建模盘口深度

## 六、文件说明

| 文件 | 说明 |
|---|---|
| `backtest/bt_data.py` | 历史数据下载与缓存（自动识别 2025 年后的微秒时间戳） |
| `backtest/bt_engine.py` | 指标、多周期对齐、信号、止盈止损计算、出场判定 |
| `backtest/run_backtest.py` | 回测主程序 |
| `backtest/sensitivity.py` | 参数敏感性扫描 |
| `results/trades.csv` | 全部交易明细 |
| `results/summary.csv` | 分标的汇总 |
| `results/backtest_report.png` | 权益曲线与分年度胜率图 |

常用命令：

```bash
# 下载数据（首次）
python bt_data.py BTCUSDT,ETHUSDT,BNBUSDT,SOLUSDT spot

# 回测
python run_backtest.py --symbols BTCUSDT,ETHUSDT,BNBUSDT,SOLUSDT --start 2018-06-01

# 反向对照 / 零成本对照
python run_backtest.py --symbols BTCUSDT --invert
python run_backtest.py --symbols BTCUSDT --fee 0 --slippage 0

# 参数敏感性
python sensitivity.py --symbols BTCUSDT,ETHUSDT --variant all
```
