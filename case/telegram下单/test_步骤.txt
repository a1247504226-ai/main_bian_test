========================================
Telegram 信号自动下单 · 使用说明
========================================

一、文件分工
----------------------------------------
telegram_listener.py   从 Telegram 拉消息 → 解析 → 写 signals.jsonl
signal_parser.py       消息解析规则（被 listener 调用，不单独跑）
signal_executor.py     读 signals.jsonl → 币安下单
.env                   全部配置（两个程序共用）

数据流：
  Telegram 频道
      ↓  telegram_listener.py 拉取
  SignalParser 解析
      ↓  追加写入
  signals.jsonl
      ↓  signal_executor.py 增量读取
  币安下单 / 改止盈止损 / 平仓


二、必须先填的 3 处（.env）
----------------------------------------
TELEGRAM_BOT_TOKEN=      bot token，形如 123456789:AAH-xxxxxxxx
TELEGRAM_CHAT_ID=        频道 id，形如 -1001234567890
TELEGRAM_PROXY=          国内必须填代理，如 http://127.0.0.1:7890

BINANCE_API_KEY / BINANCE_API_SECRET 你已经填好了。
注意：当前 BINANCE_ENV=TEST，必须配"在 testnet.binancefuture.com 单独注册的"
测试网 Key。如果 riuf... 是实盘 Key，--check 会报 -2015 Invalid API-key。
测试网和实盘的 Key 完全不通用，这一点无法靠改配置绕过。


三、启动顺序（开两个命令行窗口）
----------------------------------------
【第 1 步】先确认能收到消息（只看不写，不下单）

    python telegram_listener.py --dump

    看到 "[消息] 频道名 | '原文...'" 就说明通了。
    收不到就检查：token、chat_id、代理。

【第 2 步】确认能连币安（不下单）

    python signal_executor.py --check

    要看到"账户余额 USDT = xxx"，说明 Key 和环境匹配。

【第 3 步】正式跑（两个窗口都开着）

    窗口1：python telegram_listener.py
    窗口2：python signal_executor.py


四、首次启动的安全设计
----------------------------------------
监听器第一次启动时，会跳过积压的历史消息，只从"当前最新"开始。
这是故意的——否则一启动就会把几小时前的信号全部回放下单。

确实需要回补最近几条：

    python telegram_listener.py --backlog 5

（会触发真实下单，谨慎）


五、三个必须注意的坑
----------------------------------------
1) BINANCE_ENV=TEST 用的是测试网。
   测试网只有 BTC/ETH/SOL 这类主流币，你的策略推的是 MUBARAK、CHIP、
   PONS 这些山寨币，测试网上根本不存在 → 所有信号都会报"未找到交易对"。
   测试网只能验流程，验不了真实信号。真实验证建议用 BINANCE_MOCK=1 离线跑。

2) EMAIL_ENABLED=1，但 MONITOR_EMAIL_FROM/TO 还是 xxx@ 占位符。
   启动时会一直报邮件发送失败。要么改成真实邮箱，要么先设 EMAIL_ENABLED=0。

3) .env 顶部的注释块里明文写着你的实盘 API Key 和 Secret。
   这份文件如果发给别人或传到网上，等于把账户交出去。建议把那段注释删掉。


六、风控开关（.env，出问题先看这几个）
----------------------------------------
SIGNAL_MAX_AGE_SECONDS=300
    超过 5 分钟的 OPEN 信号直接跳过。执行器停机后重启，不会拿几小时前的
    旧价位去开仓。TP / 平仓不受此限制。

TPSL_SANITY_PCT=0.5
    止盈止损价格偏离现价超过 50% 的一律丢弃。用于兜底"不带币对的止盈止损"
    被套用到错误持仓上（比如 BTC 持仓收到 ETH 的价格）。

SYMBOLLESS_TP_CLOSE_MODE=SKIP
    不带币对的止盈/平仓消息直接跳过。真实数据里这类绝大多数是营销播报，
    猜错标的就会平错仓。改成 ANCHOR 才会按"上一条下单"去推断。

ADOPT_UNKNOWN_POSITIONS=1
    交易所上有、本地没记录的仓位会被自动接管并挂上 ±7% 保护。
    如果你在同一个账户里还手动交易别的币，把那些币写进 ADOPT_EXCLUDE_SYMBOLS，
    否则体检会把手动仓接管过去。

ENABLE_ADD=0
    补仓默认关闭。开启后才会按"补仓：0.01533"这类价位挂 LIMIT 单。

SYNC_BUDGET_SECONDS=60
    单轮体检最多占用 60 秒，防止网络故障时体检卡死、信号得不到处理。


七、排查
----------------------------------------
telegram_listener.log   监听器日志（每条收到的消息 + 解析结果）
logs/                   执行器日志（下单、改单、对账）
executor_state.json     执行器状态（持仓记录、锚点币对、文件游标）
telegram_state.json     监听器状态（update_id 游标，删掉会重新跳过积压）
