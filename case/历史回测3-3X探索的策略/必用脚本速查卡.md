# 必用脚本速查卡

> 打印或截图存手机。**只有 7 个 `.bat` 需要你双击**，其余全是它们调用的零件。

---

## 你只需要点这 7 个

| 脚本 | 什么时候点 | 会下单吗 |
|---|---|---|
| **`run_all.bat`** | ★ 每天（或让定时任务跑） | ❌ 永不 |
| **`install_tasks.bat`** | ★ 一次性建好 3 个定时任务（会自动提权） | ❌ 永不 |
| **`run_switch.bat`** | ★ 想切换「只推送 ⇄ 真下单」 | ⚠️ 选 ON 后，下次跑 `run_trade.bat` 才会 |
| **`run_status.bat`** | 想知道现在什么状态、该下多少 | ❌ 永不 |
| `run_sync_check.bat` | 实盘前 / 每月检查 | ❌ 永不 |
| `run_trade.bat` | 手动执行一次下单 | ✅ 开关打开时才会 |
| `run_alert.bat` | 每小时跑（止损/爆仓提醒） | ❌ 永不 |

`uninstall_tasks.bat` 用来删定时任务；`check_files.bat` 用来查文件有没有拷漏。

## 三个开关字段（`config.json` 顶部）

```json
"_master_switch": {
  "mode": "observe",                    ← observe = 只推送 | live = 真下单
  "i_understand_real_money": false      ← 必须同时为 true
}
```

| mode | confirm | 结果 |
|---|---|---|
| `observe` | 任意 | ✅ 只发邮件，绝不下单 |
| `live` | `false` | ⛔ 仍不下单，并报错提示 |
| `live` | `true` | ⚠️ 真实下单已放行 |

> 用 `run_switch.bat` 会自动把 `mode`、`i_understand_real_money`、
> `trade.dry_run` 三个字段一起设好，不用手动管。

## 对接币安，只有 3 件事要做

| # | 做什么 | 在哪做 |
|---|---|---|
| 1 | 创建 API Key（**只勾「允许合约」**，不勾提现/划转） | 币安 → API 管理 |
| 2 | 加 **IP 白名单** | 币安 → API 管理 → 编辑限制 |
| 3 | 账户改成 **「单向持仓」** 模式 | 币安 App → 合约 → 设置 → 持仓模式 |

然后把 Key / Secret 填进 `config.json` 的 `trade.apiKey` / `trade.apiSecret`。

> ⚠️ **第 3 条不做会直接报错**：本策略是单向净头寸，
> 双向持仓模式下同一交易对有多空两条持仓记录，仓位会算错，程序会拒绝运行。

> ⚠️ **第 2 条强烈建议做**：程序为兼容各种网络关闭了 HTTPS 证书校验，
> 加白名单后即使密钥泄露别人也用不了。

## 定时任务：不用手打命令

**双击 `install_tasks.bat`**（弹 UAC 点「是」），一次建好 3 个：

| 任务名 | 频率 | 跑什么 |
|---|---|---|
| `BTC_Signal_Push` | 每天 **08:05** | `run_daily.bat` — 推日报 |

| `BTC_Auto_Trade` | 每天 **08:10** | `run_trade.bat` — 自动下单（默认空转） |

删除：双击 `uninstall_tasks.bat`。
查看：`schtasks /Query /TN "BTC_Signal_Push"`

## 想跑 A 档或 C 档？两个地方改

默认只跑 B 档，但 **A / B / C 三档一直都在**，随时可切：

### ① 邮件推送：跑哪几档

`run_all.bat` 一次推**全部三档**（A+B+C 合并一封邮件），不用改配置。

| 命令 | 效果 |
|---|---|
| `run_all.bat` | 三档合并一封（默认，推荐） |
| `run_all.bat --daily` | 不管方向变没变，每天都发一封（定时任务用的就是这个） |

想只看某一档：在文件夹地址栏输 `cmd` 打开命令行，跑
`strategy_a.py` / `strategy_b.py` / `strategy_c.py`（需要 Python 在 PATH 里）。
**一般不需要这么做** —— 合并一封反而更好看，反正邮件里三档数字都列着。

### ② 自动下单：只跑哪一档

`config.json` → `trade.profile`，填 `"A"` / `"B"` / `"C"` 之一：

```json
"trade": {
  "profile": "B",      ← 改成 "A" 或 "C" 即可
```

**只能填一个**（原因：仓位按账户总余额算，跑两档会互相覆盖）。

### ③ 每档的参数都能改

```json
"profiles": {
  "A": { "name": "A 保守", "vol_target": 0.02, "equity": 1000.0 },
  "B": { "name": "B 推荐", "vol_target": 0.03, "equity": 1000.0 },
  "C": { "name": "C 激进", "vol_target": 0.05, "equity": 1000.0 }
}
```

| 字段 | 含义 | 怎么改 |
|---|---|---|
| `vol_target` | 目标日波动，**这就是风险旋钮** | 越大收益和回撤同比例放大。B 档 0.035 = 「比B激进比C温和」 |
| `equity` | 该档的本金基准 | **只影响邮件里显示的保证金/数量**，不影响实际下单 |
| `name` | 邮件里显示的名字 | 随便改 |

**三档互相独立**：改 C 档不影响 A 档（已实测验证）。改完存盘立即生效。

> ⚠️ 实盘自动下单时，实际仓位按**交易所真实余额**自动缩放。
> 所以「想降档」最直接的办法是**少放点钱进合约账户**，不用改配置。

## 想只跑 BTC，还是跑四币合一？改一个词

**这是同一个开关，信号邮件和自动下单都跟着它走**（不用改两处）。

`config.json` 里：

```json
"run_mode": "multi",     ← multi = 四币等权 | single = 只跑下面 symbol 那一个币

"symbol":  "BTCUSDT",                                        ← single 模式用这个
"symbols": ["BTCUSDT", "ETHUSDT", "BNBUSDT", "SOLUSDT"],     ← multi 模式用这些
```

| `run_mode` | 效果 |
|---|---|
| `"single"` | 只跑 `symbol`（默认 BTCUSDT），**1000 U 全押 BTC** |
| `"multi"` | 跑 `symbols` 里所有币，**每个币分到 账户总权益 ÷ 币数** |

> 想跑 3 个币？把 `symbols` 里删掉一个就行，**不用改别的**。
> 想跑 5 个币？加一个 `"XRPUSDT"` 就行。

### 两种模式下的钱怎么分

| | 仅 BTC（single） | 四币合一（multi） |
|---|---|---|
| 每个币拿多少 | 账户总权益 **全部** | 账户总权益 **÷ 4** |
| 1000 U 本金，BTC 下多少 | 名义 ≈ 788 U（保证金 ≈ 263 U） | 名义 ≈ 296 U（保证金 ≈ 99 U） |
| 一个币爆仓会怎样 | 账户基本归零 | **只亏那一个币的保证金**，其余三个照跑 |

> 实测（2021-01-01 起 8 个起始日窗口）：四币等权**动态再平衡 8/8 全胜**
> 「固定分配各跑各的」。账户涨了每币配额自动等比放大，不用手动改。

### 邮件里两个视角都会给你

四币模式下，邮件**同时**列出：

1. **① 四币等权** —— 你实际要下的单（每币一行，含合计保证金）
2. **② BTC 单跑参照** —— 把 1000 U 全押 BTC 会长什么样（**只是对照，不要照着下单**）

这样你能一眼看出「分散」到底把 BTC 那份削了多少。

### 临时切换（不改配置文件）

```bash
run_trade.bat --single                          # 这次只跑 BTC
run_trade.bat --multi                           # 这次跑四币
run_trade.bat --symbols BTCUSDT,SOLUSDT         # 这次只跑这两个
run_all.bat   --single                          # 信号邮件也支持同样参数
run_status.bat --multi                          # 状态总览也支持
```

### ⚠️ 小额本金要注意「最小名义」

币安对每个交易对有**最小下单名义**（`min_notional`）。
四币模式下 BTC 只分到 250 U，如果 BTC 的最小名义门槛高，调仓会被拒。

**跑一次就知道**（会逐币打印 `min_notional`）：

```bash
run_sync_check.bat
```

输出里找这一段：

```
6. 交易精度参数（逐币）★ 决定小额本金能否正常下单
  BTC    qty_step=0.001      min_qty=0.001     min_notional=  100.0 U
  ETH    qty_step=0.001      min_qty=0.001     min_notional=   20.0 U
  ...
```

如果出现 `[!!] 需要调仓 … < 交易所最小名义 …` → 说明本金偏小，
**提高本金**或**减少币数**（`symbols` 里删掉门槛高的那个）。

## 每天那封日报里有什么

方向没变也会每天推一封（定时任务 `BTC_Signal_Push`，每天 08:05），
内容分三块：

| 块 | 内容 |
|---|---|
| ① 要下的单 | 每币的保证金 / 下单数量 / 名义（四币模式下逐币列） |
| ② **建仓价** | 这一波是什么价位进的、建了多久、现在赚多少 |
| ③ BTC 单跑参照 | 四币模式下才有，只是对照，**不要照着下单** |

**② 建仓价怎么读**：

```
建仓价      83,664 USDT    ← 2026-09-29 建立，已持有 6 天
当前浮动    价格 +2.51%　保证金口径 +7.54%（3×）
```

- 建仓价 = **方向确认那根K线的收盘价**（你当时该下单的价位）
- 方向变了它自动重置；方向没变就一直沿用最初那个
- `保证金口径` = 价格变动 × 3（名义 = 保证金 × 3）
- 显示 `本次新建仓` = 今天方向刚变，建仓价就是今天

> 想知道持仓赚没赚，看这一行就够了，不用自己翻历史邮件。

## 邮件里的「止损提醒」要配吗？——**不用**

**不用配，也不该照着它手动砍仓。** 默认已经配好（吊灯 5×ATR），它只是个参考价位。

| | 是什么 | 会自动执行吗 |
|---|---|---|
| **止损提醒** | 参考价位，价格到这儿说明回撤很深了 | ❌ 不挂单、不平仓，只是印在邮件上 |
| **爆仓价** | 交易所硬底（3× 逐仓 = 建仓价 × 0.6717） | ✅ 会，币安强平，只亏该币保证金 |
| **方向反转** | 5 组参数翻向 → 邮件让你「平仓/反手」 | ✅ 会（开了自动下单时）。**这才是真正的止损** |

**为什么别照着它砍**：回测实测，BTC 上挂吊灯 3×ATR 止损会把 9 年 **114.89× 打到 2.29×**，
砍掉的都是后来回本的大单。最优止损距离跨资产还不一致（SOL 上 0.64× → 0.16×）。

**真要调**（`config.json` → `risk` 段，**只影响邮件印什么、什么时候发提醒**）：

| 字段 | 含义 |
|---|---|
| `stop_mode` | `none` 不显示 / `trail_atr` 吊灯移动止损（默认）/ `fixed_pct` 固定百分比 |
| `trail_atr` | 吊灯倍数，默认 `5.0`。调小 = 更近、更容易被打到 |
| `fixed_stop_pct` | `fixed_pct` 时生效，`0.10` = 10% |
| `take_profit_pct` | 止盈位，`0` = 不设（推荐） |
| `liq_warn_pct` | 距爆仓价多少以内发风控提醒，默认 `0.10` |
| `max_alerts_per_day` | 风控提醒每天最多几封，默认 `3` |

> ⚠️ 改这些**不改变策略的买卖行为**。策略的离场只有一条：**方向反转**。

## 要不要换成 4h / 1h / 15m？——**不要**

9.1 年 BTC 数据实测（完整报告：`BTC多周期对比报告.html` + `BTC细周期策略合理性报告.html`）：

| 周期 | 只改 interval（参数不动） | 参数同步放大 |
|---|---|---|
| **1d（现在）** | **16.94×** ｜ 回撤 51.2% | — |
| 4h | 4.47× ｜ 回撤 63.1% | 20.35×（×6）｜ 回撤 55.2% |
| 1h | **0.00×（归零）** | 24.75×（×24）｜ 回撤 54.9% |
| 15m | **0.00×（归零）** | 33.89×（×96）｜ 回撤 59.4% |

五条硬结论：

1. **只改 `interval` 不改参数 = 送钱。** 1h / 15m 直接归零（翻转次数从 344 涨到 9,173 / 39,535）。
2. **参数放大后收益更高，但回撤一起涨**，年化 ÷ 回撤四者几乎一样（0.73 / 0.73 / 0.79 / 0.82）。
   换周期不是白捡收益。
3. **参数在细周期上极不稳定**：15m 的参数网格给出 13.55× ~ 129.34×（9.5 倍差距）；
   用 2018-2021 挑的"最优参数"到 2022-2026 全部失效（秩相关 ≈ 0，等于随机）。
4. **细周期上只有「低频 + 长持仓」的顺势策略能活。** 均值回归 / RSI / 日内时段策略全灭——
   布林均值回归 **连零成本对照都是 0.00×**（信号本身没 edge），时段策略样本外年化 −98% ~ −99.8%。
5. **唯一看着很香的「4h Donchian 20 天」（全期 34.06×、样本外 2.65×）过不了体检**：
   参数网格 3.2 倍锯齿、**样本外秩相关 ρ = −0.55（负数，调参是负作用）**、优势集中在 2017-2020。
   而最公平的对比（趋势时间等价，不挑参数）样本外：1d 1.84× / 4h 1.55× / 1h 1.83× / 15m 2.18×，
   **风险调整后 1d 的 Calmar 0.347 反而最好**。

**结论：保持日线。** 细周期上最好的结果也只是「打平」，运维成本却是 6 倍（4h）到 96 倍（15m）。
真想提高收益，走「加币种分散」或「日线上把趋势和突破组合起来」，别换周期。

## 常用命令行（不双击时用）

在文件夹地址栏输入 `cmd` 回车，就能在这里打开命令行：

```bash
run_all.bat --dry-run      # 算信号，不发邮件
run_all.bat --test         # 发测试邮件
run_all.bat --force        # 强制发一封信号邮件
run_all.bat --single       # 信号邮件只看 BTC
run_trade.bat --check      # 只读对账，不下单
run_trade.bat --dry-run    # 预演下单
run_trade.bat --single     # 这次只跑 BTC
run_trade.bat --symbols BTCUSDT,SOLUSDT   # 这次只跑这两个币
run_alert.bat --dry-run    # 看风控是否触发
run_sync_check.bat         # 逐币对账（会打印各币 min_notional）
```

```
① run_sync_check.bat     → 看到「✓ 可以上线」
```

## 出错先看这里

| 现象 | 处理 |
|---|---|
| 没收到邮件 | 查垃圾箱 → `run_all.bat --test` → 看 `logs\live_ABC_*.log` |
| 报「账户当前是双向持仓模式」 | 币安 App → 合约 → 设置 → 持仓模式 → 单向持仓 |
| 报 `-2015` | API 的 IP 白名单失效，回币安后台更新你当前公网 IP |
| 报 `-1021` | 系统时间不准，开启自动同步 |
| 报 `-2019` | 可用保证金不足，降低下单名义或加钱 |
| 报「拒绝真实下单」 | 开关没开全，`run_switch.bat` 重新 ON |
| 报「发现未完成的意图」 | 上次下单可能中断。先 `run_sync_check.bat` 核对持仓，确认后加 `--force` |
| 下单失败 | **立刻登录币安人工核对持仓**，不要重复跑 |
