# 上手教程 · B 档实盘（对接币安）

> 目标：**先只收邮件、不下单**，观察一段时间后再决定是否让程序自动下单。
> 全程只需要动一个开关。所有脚本都在同一个文件夹里，**搬到哪台电脑都能跑**。

## 第 2 步：设成每天自动推送

日线在 **UTC 00:00 收盘 = 北京时间 08:00**，所以任务设在 **08:05**。

**双击 `install_tasks.bat`** → 会弹 UAC，点「是」。它会一次建好 3 个任务：

| 任务名 | 频率 | 跑什么 | 干什么 |
|---|---|---|---|
| `BTC_Signal_Push` | 每天 **08:05** | `run_daily.bat` | 推日报（方向/保证金/数量） |
| `BTC_Price_Alert` | **每小时** | `run_alert.bat` | 风控提醒（止损/爆仓预警） |
| `BTC_Auto_Trade` | 每天 **08:10** | `run_trade.bat` | **自动下单（默认空转）** |

> **`BTC_Auto_Trade` 现在装上是安全的**：只要总开关还是 `observe`，
> 它每次跑完只会写一行日志，不会提交任何订单。
> 等你哪天开了总开关，它就自动开始下单 —— 不用再回来建任务。

想删掉：双击 `uninstall_tasks.bat`。

## 第 3 步：读懂邮件

邮件长这样（当前真实数据）：

```
【BTC信号·3倍合约】每日日报 · 方向未变
==================================================
数据K线：2026-10-04 日线（已收盘）
当前价格：86,530 USDT　日波动率：2.54%
--------------------------------------------------
▌B 推荐（目标日波动 3%）  ← 你跑的这一档
  方向：多 ▲
  保证金：394 U        ← 划这么多进合约账户
  下单数量：0.013664 BTC  ← 币安下单框填这个
  名义价值：1,182 USDT（= 保证金 × 3）
  参数明细：8/24→多　10/30→多　12/36→多　15/45→多　20/60→多
  止损提醒位：76,242　爆仓价：58,119（距现价 -32.8%）
--------------------------------------------------
▌其他档位参考
  档位   方向   保证金      数量BTC
  A 保守  多     263 U     0.009109
  C 激进  多     657 U     0.022773
```

**你只需要看这 4 个字段：**

| 看什么 | 意思 |
|---|---|
| 标题有没有「**方向变化**」 | 有 → 要动手换仓；「方向未变」→ 不用管 |
| **方向** | 做多还是做空 |
| **保证金** | 要划多少钱进合约账户 |
| **下单数量** | 币安下单框填这个数字 |

### 为什么保证金不是固定值？

```
名义价值 = 权益 × 敞口        敞口 = min(3.0, 目标波动 ÷ 当日波动)
保证金   = 名义价值 ÷ 杠杆      ← 是「名义」÷ 杠杆，不是「本金」÷ 杠杆
```

**保证金不是 1000÷3=334，它每天都在变。** B 档 9 年实测分布：

| 最小 | 10 分位 | 中位 | 90 分位 | 最大 |
|---|---|---|---|---|
| 10 U | 71 U | 201 U | 350 U | 565 U |

变化来自两件事：① 波动率（波动大 → 自动缩仓）；② 5 组参数方向是否一致（不一致时互相抵消）。

> **所以每次邮件给的保证金就是这次该划的钱。** 不用去记什么固定数字。

## 第 5 步：对接币安（★ 你要改的就这一处）

### 5.1 创建币安 API 密钥

登录币安 → 头像 → **API 管理** → 创建 API → 选 **系统生成**

- **权限**：只勾 **「允许合约」**（Enable Futures）
- **不要勾**：提现（Withdraw）、划转（Transfer）
- IP 白名单：稍后填（见 5.2）

创建后给你 **API Key** 和 **Secret Key**，Secret **只显示一次**，先复制保存。

### 5.2 加 IP 白名单（★ 强烈建议）

币安 → API 管理 → 找到刚建的 Key → **编辑限制** → **限制访问 IP**。

查你的公网 IP：

```powershell
(Invoke-RestMethod "https://api.ipify.org?format=json").ip
```

> **为什么强烈建议**：本程序为了兼容各种网络环境，
> 关闭了 HTTPS 证书校验（`ssl.CERT_NONE`）。
> 加了 IP 白名单，即使密钥被截获，别人也用不了。

> **注意**：家庭宽带 IP 会变，变了要回来更新，否则下单报 `-2015`。

### 5.3 确认账户是「单向持仓」模式（★ 必做）

币安 App：**合约 → 右上角设置 → 持仓模式 → 选「单向持仓」**

> 本策略是**单向净头寸**（5 组参数合成一个方向）。
> 如果你账户是「双向持仓」，程序会**直接拒绝运行**并提示你改回来 ——
> 因为双向模式下同一交易对会有多空两条持仓记录，仓位会算错。

### 5.4 填进配置

编辑 `config.json`，找到 `trade` 段：

```json
"apiKey": "在这里填你的币安API Key",
"apiSecret": "在这里填你的币安API Secret",
```

替换成真实密钥（**保留引号**）。

> **更安全的做法**：不写文件，改用环境变量（程序优先读环境变量）
> ```powershell
> setx BINANCE_API_KEY "你的Key"
> setx BINANCE_API_SECRET "你的Secret"
> ```
> 设完要**重开命令行窗口**才生效。

### 5.5 检查一个数字

```json
"max_order_notional": 3000
```

这是**单次下单名义上限**（防手滑/防配置写错）。
建议设成 **本金的 3~4 倍**。你本金 1000 U → 保持 3000 即可；
以后加钱到 5000 U，就改成 15000。

## 第 6 步：检查账户连接（只读，不下单）

双击 **`run_sync_check.bat`**。

它做 8 项检查，**全程只读、绝不下单**：总开关 → 密钥 → 时间同步 → 余额 →
持仓 → 交易对精度 → 杠杆设置 → 目标仓位差异。

**重点看最后一行结论：**

- `✓ 可以上线` → 一切正常
- `✗` 或「问题」→ 按提示修，别急着往下走

| 报错 | 原因 | 解决 |
|---|---|---|
| `-2015` | Key 无效 / IP 不在白名单 / 没开合约权限 | 回 5.1、5.2 |
| `-1021` | 本机时间和币安服务器偏差大 | 系统设置 → 时间 → 自动同步 |
| `-2019` | 可用保证金不足 | 降低下单名义，或加钱 |

## 第 8 步：开启实盘

### 8.1 先小额

第一次只放 **1000~5000 U** 进合约账户，跑一两个月。

> 仓位是按**账户余额**自动缩放的。放 5000 U 就等于在用 5000 U 本金跑 B 档，
> 和「10 万本金只放 5 万进去」**完全等价**（本质是降档）。

### 8.2 打开开关

双击 **`run_switch.bat`** → 选 **3 (ON)** → 输入大写 **`YES`** 确认。

它会自动设置四个字段：

```json
"_master_switch": { "mode": "live", "i_understand_real_money": true },
"trade": { "enabled": true, "dry_run": false }
```

### 8.3 真跑第一次

双击 **`run_trade.bat`**。它会：拉K线算信号 → 连币安读余额和持仓 →
算目标仓位并比对 → 有偏差就下单 → 发一封「已执行」邮件。

**看到邮件里写着「已执行」就算成功了。**

### 8.4 交给定时任务

**不用再手动建任务** —— 第 2 步的 `install_tasks.bat` 已经把
`BTC_Auto_Trade`（每天 08:10）建好了，之前它一直空转，现在自动开始工作。

> **但建议先手动跑 1~2 周**（每天双击 `run_trade.bat`），
> 确认每次动作都符合预期，再完全交给定时任务。

## 第 9 步：怎么停下来

1. **一键关**：双击 `run_switch.bat` → 选 **2 (OFF)**
2. **手改**：`config.json` 里 `_master_switch.mode` 改回 `"observe"`

**关掉后会发生什么：**

- ✅ 邮件推送继续（不受影响）
- ✅ 已开的仓位**保持不动**（程序不会帮你平仓）
- ⛔ 不会再有新的下单动作

> **注意**：关开关 ≠ 平仓。如果关闭时还有持仓，需要你自己决定继续持有还是手动平掉。
> 建议要么开着，要么手动全平 —— 别让它脱离策略管理。

## 必须知道的几件事

### 1. 会爆仓，但不会归零

3× **逐仓**的爆仓距离是 **-32.83%**（= 1 − 1/3 + 0.5%），只跟杠杆有关，跟仓位大小无关。

**9 年回测结果：A/B/C 三档各爆仓 1 次，都在 2018-01-16**（BTC 单日 -33%）：

| 档 | 期末权益 | 最大回撤 | 爆仓损失 |
|---|---|---|---|
| A 保守 | 10.00× | -43.53% | 13.1 U |
| **B 推荐** | **19.40×** | **-55.26%** | **22.6 U** |
| C 激进 | 41.22× | -71.13% | 47.2 U |

**逐仓只亏那一笔保证金，账户剩余资金不动** —— 那天三档各只掉 0.9% / 1.4% / 2.3% 的权益。

**但要清楚最坏情况**：保证金占权益的比例是会变的。

| 档 | 中位 | 90 分位 | 历史最高 |
|---|---|---|---|
| A | 13.7% | 22.7% | 33.6% |
| **B** | **19.8%** | **32.9%** | **52.3%** |
| C | 30.8% | 52.1% | 94.3% |

也就是说，**B 档最坏情况爆仓会亏掉约一半本金**，C 档接近归零。
之所以 9 年实际只亏 1.4%，是因为**暴跌必然伴随高波动，而仓位是按波动率自动调的** ——
两者天然对冲。

### 2. 保证金占用是浮动的

见第 3 步的分布表。**账户里要留够钱**，否则会因为「可用保证金不足」下单失败（报 `-2019`）。

### 3. A / B / C 三档都在，随时可切

**邮件推送**：`run_all.bat` 一次推**全部三档**（合并一封），不用改配置。
想只看某一档，在文件夹里打开命令行（地址栏输 `cmd`）跑
`strategy_a.py` / `strategy_b.py` / `strategy_c.py`（需要 Python 在 PATH 里）。

**自动下单**：`config.json` → `trade.profile`，填 `"A"` / `"B"` / `"C"` 之一。默认 `"B"`。

**只能填一个档位。** 跑两个会互相覆盖仓位（都按账户总余额算）。
B 和 C 的相关系数是 **0.99**，同时跑两档等同于跑一个中间档。

**每档参数都能改**（三档互相独立）：

```json
"profiles": {
  "A": { "vol_target": 0.02, "equity": 1000.0 },
  "B": { "vol_target": 0.03, "equity": 1000.0 },   ← 想调风险改这里
  "C": { "vol_target": 0.05, "equity": 1000.0 }
}
```

`equity` = 你投在这一档的本金，**只影响邮件里显示的保证金/数量**。
`vol_target` = 风险旋钮，想「比 B 激进、比 C 温和」就把 B 改成 `0.035`。

### 4. 权益口径（与回测一致）

下单时用的是**币安实时余额**（钱包余额 + 该仓位浮动盈亏），
和你 `config.json` 里填的 `equity` 无关 —— 那个只用于邮件显示。

```
目标名义 = (钱包余额 + 浮动盈亏) × 敞口
```

> 所以：**你往合约账户里放多少钱，程序就按多少钱算仓位。**
> 想「降档」就直接少放钱，不用改配置。

### 5. 幂等保护

同一天同一方向只会下单一次。程序中途崩了重启也不会重复下单。
看到日志说「幂等命中……跳过」是正常保护，不是故障。

### 6. 日志在哪

`logs\` 目录。出任何问题，先看当天的日志。

| 文件 | 内容 |
|---|---|
| `logs\live_ABC_日期.log` | 信号推送日志 |
| `logs\trade_日期.log` | 下单日志 |
| `logs\sync_check_日期.log` | 对账日志 |
| `logs\alert_日期.log` | 风控提醒日志 |

## 出问题了怎么办

| 现象 | 处理 |
|---|---|
| 没收到邮件 | 先查垃圾箱；再跑 `run_all.bat --test`；再看 `logs\live_ABC_*.log` |
| 说「尚未配置密钥」 | 回第 5.4 步填 `config.json` |
| 说「账户当前是双向持仓模式」 | 回第 5.3 步改成单向持仓 |
| 报 `-2015` | IP 变了，回第 5.2 步更新白名单 |
| 报「拒绝真实下单」 | 开关没开全，双击 `run_switch.bat` 重新 ON |
| 报「发现未完成的意图」 | 上次下单可能中断。先跑 `run_sync_check.bat` 人工核对持仓，确认无误后加 `--force` |
| 下单失败但邮件说失败 | **立刻登录币安人工核对持仓**，别重复跑 |
| 想确认到底下没下 | 跑 `run_status.bat`，看持仓对照段 |

## 一句话总结

1. 双击 `run_all.bat` → 收邮件（现在就可以开始）
2. 双击 `install_tasks.bat` → 3 个定时任务全自动
3. 观察 2 周以上，手动小额练手
4. **对接币安**：改 `config.json` 的 `apiKey`/`apiSecret` + 加 IP 白名单 + 账户设单向持仓
5. 跑 `run_sync_check.bat` 确认连接 → `run_trade.bat --dry-run` 预演
6. 小额入金 → `run_switch.bat` 选 ON → 开跑
7. 想停就 `run_switch.bat` 选 OFF

**全程只有一个开关需要你操心。其余交给脚本。**
