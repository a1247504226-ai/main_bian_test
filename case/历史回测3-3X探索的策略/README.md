# A/B/C 杠杆合约实盘信号推送

把回测出来的 A（保守）/ B（推荐）/ C（激进）三档策略做成可长期稳定运行的实盘脚本，
**方向变化时发信号邮件，价格触及风控位时发提醒邮件**，由你手动操作。

---

## 一、先搞清楚：止盈止损是怎么工作的

这是最容易误解的一点。**本策略的止盈止损是「信号触发」，不是「价格触发」。**

| | 触发方式 | 谁通知你 |
|---|---|---|
| **止损** | 方向反转（EMA 快线下穿慢线） | 每日信号邮件 → 标题写「方向变化：多→空」 |
| **止盈** | 同样靠方向反转，让利润奔跑 | 同上 |
| **硬底** | 3× 逐仓爆仓价（约 -33%） | 每封邮件里的「风控位」 |
| **额外保险** | 价格触及止损位/爆仓位 | `alert.py` 单独发提醒 |

**为什么不用固定止盈止损？** 回测给出的答案很明确：

- 固定止盈会砍掉贡献全部收益的那几笔大单（加密资产收益极度右偏）；
- 固定止损距离的最优值是**锯齿状**的（1.69→1.81→2.24→1.63→1.92），不是光滑最优，
  换个资产就失效（SOL 上倍数比从 0.64× 掉到 0.16×）——**这是过拟合**；
- 吊灯止损 3×ATR 会把 BTC 的 114.89× 打到 **2.29×**。

所以策略本身只用信号出场。但如果你想要「到价提醒」作为极端行情的保险，用 `alert.py`。

## 三之二、总开关（唯一需要你在意的地方）

**所有与下单有关的开关，全部集中在 `config.json` 最顶部的 `_master_switch`：**

```json
"_master_switch": {
  "mode": "observe",                    // observe = 只推送  |  live = 真下单
  "i_understand_real_money": false      // 必须同时为 true 才会真下单
}
```

| mode | confirm | 效果 |
|---|---|---|
| `observe` | 任意 | ✅ **只推送信号，绝不下单**（默认，观察期用这个） |
| `live` | `false` | ⛔ 仍然不会下单（双保险未放行，并会报错提示） |
| `live` | `true` | ⚠️ **真实下单已放行** |

**两种切换方式（任选其一）：**

1. **一键批处理（推荐）**：双击 `run_switch.bat`，按菜单选。
   选 ON 时需要手动输入大写 `YES` 才会生效。
2. **手改配置**：编辑 `config.json` 顶部两行（保留引号）。
   > 注意：真正的下单还要求 `trade.dry_run = false`。
   > 用 `run_switch.bat` 会自动帮你三个字段一起设好，不用手动管。

`trade.enabled` 这个旧字段现在由总开关自动决定，**不需要也不能单独改**。

## 四、配置定时任务（Windows）

日线在 **UTC 00:00 收盘 = 北京时间 08:00**。建议：**信号每天 08:01 跑一次，风控提醒每小时跑一次**。
（必须 ≥08:01，让 API 的「刚开盘那根」来得及出现，配合 `keep_closed` 取上一根已收盘 K 线。）

以**管理员身份**打开 PowerShell：

```powershell
$dir = "C:\Users\hongji\WorkBuddy AI\2026-09-29-21-48-51\btc_lev\live"

# ① 每日信号推送 08:01
schtasks /Create /TN "BTC_Signal_Push" /TR "`"$dir\run_daily.bat`"" /SC DAILY /ST 08:01 /F

# ② 风控价格提醒 每小时
schtasks /Create /TN "BTC_Risk_Alert" /TR "`"$dir\run_alert.bat`"" /SC HOURLY /F

schtasks /Run /TN "BTC_Signal_Push"       # 立即试跑信号
schtasks /Run /TN "BTC_Risk_Alert"        # 立即试跑提醒
```

删除任务：`schtasks /Delete /TN "BTC_Signal_Push" /F`

> 电脑关机/休眠时任务不会执行。任务计划程序里可勾选「如果错过计划，尽快启动任务」来补跑。
> 另外默认「仅在用户登录时运行」，建议到图形界面改成「不管用户是否登录都要运行」。

## 五、风控提醒配置（`config.json` 的 `risk` 段）

```json
"risk": {
  "stop_mode": "trail_atr",     // none | trail_atr | fixed_pct
  "trail_atr": 5.0,             // 移动止损 = 持仓最高价 − 5×ATR
  "fixed_stop_pct": 0.10,       // stop_mode=fixed_pct 时生效
  "take_profit_pct": 0.0,       // 止盈百分比，0 = 不设
  "liq_warn_pct": 0.10,         // 距爆仓价 <10% 时预警
  "max_alerts_per_day": 3       // 每天最多几封，防刷屏
}
```

- `stop_mode: "none"` → `alert.py` 只做爆仓预警（推荐，最不干扰策略）。
- `trail_atr` 是**移动**止损：仓位涨上去，止损位跟着抬，锁定利润。
- 触发后同类提醒**当天只发一次**，不会反复轰炸。

### 手动设定你的真实成本价（可选）

`signal_state.json` 里的 `entry_px` 默认取「首次运行时那根 K 线的收盘价」。
如果你**已经持仓**且成本价不同，直接改这个值即可，`fixed_pct` 模式的止损位会按它算：

```json
"B": { "entry_px": 92000.0, ... }
```

（`trail_atr` 模式只看持仓期间的最高价，与 `entry_px` 无关。）

## 六、策略逻辑（与回测完全一致）

**方向信号**：5 组双均线参数等权集成 —— `8/24`、`10/30`、`12/36`、`15/45`、`20/60`。
每组 `EMA快 > EMA慢` 做多，否则做空。5 组各自独立持仓，净方向是它们的合成。

**仓位公式**：

```
日波动率 = ATR14 ÷ 当前价
账户敞口 = min(3.0, 目标日波动 ÷ 日波动率)
下单名义 = 权益 × 账户敞口
占用保证金 = 下单名义 ÷ 3      （3× 逐仓）
```

波动大自动缩仓、波动小自动加仓，让「每天的风险」保持恒定。

**三档区别**：只有「目标日波动」不同 —— A 用 2%、B 用 3%、C 用 5%。
回测（BTC 9.12 年）：A 21.78× / 回撤 -39.9%，B 53.71× / -50.3%，C 171.75× / -64.7%，全部零爆仓。

**信号邮件里会直接告诉你手动操作什么**，例如：

```
★ 需要你手动执行的操作
  B档（B 推荐）：平掉多头 0.134415 BTC → 开空头 0.134415 BTC
```

## 八、稳定运行的设计

| 措施 | 说明 |
|---|---|
| 只用**已收盘**K线 | 未收盘的K线价格还在变，用它发信号 = 误报。按 `close_time <= 当前时间` 过滤 |
| 只在**方向变化**时发信号 | 每天推「继续持有」是噪音。用 `signal_state.json` 比对 |
| 提醒**每天限次** | `max_alerts_per_day`，同类提醒当天只发一次 |
| 首次运行只发说明信 | 不会误报一笔「买入」 |
| 数据/邮件各重试 3 次 | 网络抖动自动重试（2s/4s、3s/6s 退避） |
| 状态**原子写入** | 先写临时文件再 rename，断电不会写坏 |
| 全量日志 | `logs/live_*.log` 与 `logs/alert_*.log`，出问题直接查 |
| 异常不静默 | 失败记日志 + 非 0 退出码，任务计划程序能发现 |
| `local_hostname` 固定 ASCII | 避免计算机名含中文导致 smtplib 的 EHLO 报 ascii 编码错（极难排查） |

## 十、🤖 对接币安自动下单（新增）

### 10.1 它做什么

前面九节是「发邮件 + 你手动操作」。这一节让它**直接替你下单**：

```
拉已收盘K线 → 算 B 档目标仓位 → 查交易所真实持仓/余额
    → 比对差异 → 风控校验 → 市价下单 → 发邮件通知成交
```

邮件角色从「操作指令」变成「成交回执」。

### 10.2 三个新增文件

| 文件 | 职责 |
|---|---|
| `binance.py` | 币安接口封装：HMAC-SHA256 签名、时间校准、杠杆/保证金模式、市价下单、精度对齐 |
| `trade.py` | 业务编排：信号 → 目标 → 差异 → 动作判定 → 幂等 → 执行 → 通知 |
| `sync_check.py` | **只读**对账自检：账户/持仓/杠杆/精度/目标差异全面体检 |

### 10.3 配置（`config.json` 的 `trade` 段）

```json
"trade": {
  "enabled": false,               // ← 总开关。false = 只对账不下单
  "apiKey": "在这里填你的币安API Key",
  "apiSecret": "在这里填你的币安API Secret",

  "profile": "B",                 // 只跑哪一档（推荐只跑一个）
  "dry_run": true,                // true = 只打印不提交

  "leverage": 3,
  "margin_type": "ISOLATED",      // 逐仓（与回测一致，强烈建议不要改）
  "set_leverage_on_start": true,  // 下单前自动把杠杆设为 3×

  "idempotent": true,             // 同一天同一方向只下单一次
  "max_order_notional": 0,        // 0 = 自动跟随（配额 × 3.15），推荐
  "rebalance_threshold": 0.05,    // 偏差 <5% 不下单，避免频繁微调

  "allow_flip": true,             // 允许一键反手（平旧+开新）
  "reduce_first": true,           // 反手先平后开，避免双向持仓

  "recvWindow": 5000
}
```

> **密钥更安全的做法**：不写文件，改用环境变量
> `BINANCE_API_KEY` / `BINANCE_API_SECRET`（程序会优先读环境变量）。

### 10.3b 只跑 BTC，还是四币合一（`run_mode`）

**一个开关同时管住信号邮件和自动下单**：

```json
"run_mode": "multi",     // multi = 四币等权 | single = 只跑下面 symbol 那一个币

"symbol":  "BTCUSDT",                                     // single 模式用
"symbols": ["BTCUSDT","ETHUSDT","BNBUSDT","SOLUSDT"],     // multi 模式用
```

| | `single`（仅 BTC） | `multi`（四币合一） |
|---|---|---|
| 每币配额 | 账户总权益**全部** | 账户总权益 **÷ 币数**（动态再平衡） |
| 1000 U 本金下 BTC 名义 | ≈ 788 U | ≈ 296 U |
| 单币爆仓 | 账户基本归零 | 只亏该币保证金（逐仓隔离） |
| 邮件 | 单币视角 | **同时**给「① 四币等权」+「② BTC 单跑参照」 |

命令行可临时覆盖（不改配置）：

```bash
python trade.py --single                        # 只跑 config.symbol
python trade.py --multi                         # 跑 config.symbols 全部
python trade.py --symbols BTCUSDT,SOLUSDT       # 指定一组
```

`run_all.py` / `status.py` / `sync_check.py` / `alert.py` 同样支持这三个参数。

> ⚠️ 每个交易对有自己的 `min_notional`。四币模式下 BTC 只分到 1/4 本金，
> 若门槛偏高会拒单。跑 `python sync_check.py` 看第 6 段「交易精度参数（逐币）」。

### 10.5 `trade.py` 命令

| 命令 | 行为 |
|---|---|
| `python status.py` | ★ 一屏总览（只读）：开关/信号/目标/账户差异，**永不下单** |
| `python trade.py --check` | 只读对账：算信号+算目标+比对持仓，**不下单不发信** |
| `python trade.py --dry-run` | 打印将执行的下单，不提交，不发信 |
| `python trade.py` | 真实下单（需总开关 `mode=live` 且 `i_understand_real_money=true` 且 `dry_run=false`） |
| `python trade.py --force` | 忽略幂等保护，强制执行一次 |

### 10.6 动作判定逻辑

| 当前持仓 | 目标持仓 | 动作 | 下单 |
|---|---|---|---|
| 空 | 空 | 无需操作 | — |
| 空 | 多/空 | 开仓 | 市价买入/卖出 |
| 多/空 | 空 | 平仓 | 反向市价 + `reduceOnly` |
| 多 | 空（或反之） | **反手** | 先 `reduceOnly` 平旧 → 再开新 |
| 同向 | 同向不同量 | 调仓 | 加仓普通单 / 减仓 `reduceOnly` |

> **反手 = 本策略的核心动作**。回测 124 笔里 **123 笔间隔 0 天**，即信号反转当天立刻反手，
> 永续在场、从不空仓等待。

### 10.7 六道安全防线

1. **`enabled=false` 默认关闭** —— 不主动打开绝不下单。
2. **`dry_run=true` 默认预演** —— 两个开关都关掉才会真实成交。
3. **`reduceOnly` 平仓** —— 平仓单永远只减仓，不会因方向搞错而反向开仓。
4. **幂等保护** —— 下单前写「意图文件」，成功后才写「完成标记」。
   同日同方向重复运行会被拦截；若发现「未完成意图」会**拒绝执行并要求人工核对**。
5. **名义上限 + 最小名义校验** —— 超过 `max_order_notional` 拒绝；低于币安 `minNotional` 拒绝。
6. **精度向下对齐** —— 数量一律按 `stepSize` **向下取整**（绝不向上，避免超出可用保证金）。

### 10.8 定时任务（自动模式下）

日线 UTC 00:00 收盘 = 北京 08:00。**信号 08:01 跑，自动下单 08:02 跑**
（错开 1 分钟，确保信号邮件先发出、状态先落盘）：

```powershell
$dir = "C:\Users\hongji\WorkBuddy AI\2026-09-29-21-48-51\btc_lev\live"

schtasks /Create /TN "BTC_Signal_Push" /TR "`"$dir\run_daily.bat`""  /SC DAILY /ST 08:01 /F
schtasks /Create /TN "BTC_Auto_Trade"  /TR "`"$dir\run_trade.bat`""  /SC DAILY /ST 08:02 /F
schtasks /Create /TN "BTC_Risk_Alert"  /TR "`"$dir\run_alert.bat`""  /SC HOURLY /F
```

> ⚠️ 自动下单模式下，`alert.py` 依然只是「提醒」——它**不会**帮你挂止损单。
> 本策略 9 年回测 124 笔 **100% 靠信号平仓，0 止损 / 0 止盈 / 0 爆仓**，
> 所以「不挂止损」不是遗漏，而是策略设计的一部分。

### 10.9 ⚠️ 风险警告（请务必读）

- **真金白银**。`trade.py` 会真实下单，配置错误可能造成直接亏损。
- **API 权限最小化**：只开「合约交易」，**绝不要开「提现」权限**。
- **白名单**：务必绑定服务器出口 IP 白名单（这是防密钥泄露的最后一道门）。
- **先小额验证**：建议首次投入不超过总资金的 10%，跑 1~2 个月确认行为一致再加码。
- **本策略回撤很大**：B 档 9 年最大回撤 **-50.3%**，2021/2022 有多段深度回撤。
  3× 逐仓爆仓价约 **-33%**（价格反向），策略靠波动率缩仓规避，但**极端跳空仍可能穿仓**。
- **网络/交易所故障**：脚本失败会发失败邮件 + 非 0 退出码，**务必配置任务计划程序的失败告警**，
  或每天检查一次 `logs/trade_*.log`。
- **切换保证金模式有限制**：币安在「有持仓或有挂单」时拒绝切换 ISOLATED/CROSSED。
  首次上线请**空仓状态**下先跑一次 `sync_check.py` 完成模式切换。

## 十一、常见问题

**Q：没有止盈止损吗？**
有，但是「信号触发」的：方向反转就是止损/止盈，信号邮件会通知你。
想要「价格触发」的提醒就配好 `risk` 段并跑 `alert.py`。

**Q：自动下单会帮我挂止损单吗？**
**不会**，这是有意的。回测显示固定止损会显著损害收益（吊灯 3×ATR 把 114.89× 打到 2.29×）。
策略的止损就是「方向反转」，由 `trade.py` 自动反手完成。若你想要额外保险，
用 `alert.py` 收到提醒后**手动**在币安 App 挂止损。

**Q：`sync_check.py` 说「不一致」怎么办？**
按 [!!] 逐条处理。最常见的三条：
① 密钥是占位符 → 填真实密钥；② 杠杆/保证金模式不一致 → 空仓时先跑一次让它自动设置；
③ 「未完成意图」→ 人工登录币安核对持仓后再 `--force`。

**Q：会不会重复下单？**
不会。三重保护：`trade_intent.json` 幂等键（交易对+日期+方向）、
`reduceOnly` 平仓、`rebalance_threshold` 阈值过滤。若中途崩溃留下「未完成意图」，
脚本会**拒绝自动重试**并要求人工确认——这是故意的，宁可漏单不可错单。

**Q：收不到邮件？**
先跑 `python run_all.py --test`。失败就看 `logs/`：多半是授权码失效，
或 163 未开启 SMTP（登录 163 邮箱 → 设置 → POP3/SMTP/IMAP → 开启并重新获取授权码）。

**Q：一天收到好几封？**
信号邮件只有方向变化才发；提醒邮件每天限 `max_alerts_per_day` 封且同类只发一次。
若频繁收到信号，说明策略在震荡区反复反手——这是趋势策略的固有弱点，不要手动干预。

**Q：能换币种吗？**
改 `config.json` 的 `"symbol"`，如 `ETHUSDT`（记得把 `run_mode` 设为 `"single"`）。
但**参数是按 BTC 拟合的**，换标的请先用回测复核
（跨资产：ETH 2.86×、SOL 0.61× 买入持有，SOL 明显跑不赢）。

**Q：能同时跑几个币吗？**
能。把 `run_mode` 设成 `"multi"`，`symbols` 里列出要跑的币即可，**等权、动态再平衡**。
9 年实测：四币等权在 8 个起始日窗口上**全部**优于「各币固定分配」；
相比只跑 BTC，回撤更低（33% vs 39%），代价是收益被摊薄。
详细对比见 `多币种对比报告.html`。

**Q：邮件里的「止损提醒」要配置吗？**
不用，默认已配好（吊灯 5×ATR）。**它不会自动执行** —— 脚本不挂止损单、不自动平仓，
只是把价位印在邮件里。策略真正的离场信号是「方向反转」。
想改显示方式/倍数看 `config.json` 的 `risk` 段，但**改它不改变策略的买卖行为**。
回测实测：BTC 上挂吊灯 3×ATR 止损会把 9 年 114.89× 打到 2.29×，不建议照着它手动砍仓。

**Q：邮件里的「建仓价」是什么？**
方向确认那根K线的收盘价，也就是你当时该下单的价位。方向变了自动重置，
方向没变就一直沿用。旁边会给出 `价格 ±x%` 和 `保证金口径 ±x%`（= 价格变动 × 杠杆），
一眼看出这一波拿了多久、赚了多少。日报（`--daily`）每天都会带上这一行。

**Q：邮件里的数量和我账户对不上？**
邮件按 `config.json` 里的 `"equity"`（默认 10000）算。改成你的实际权益即可。
**自动下单模式下不用改**——`trade.py` 会自动读交易所真实余额并等比缩放目标仓位。
