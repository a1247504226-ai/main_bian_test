「建仓价」是什么？怎么算的？

建仓价 = 方向确认那根K线的收盘价，也就是你当时该下单的价位。

方向变了它就自动重置成新的价格，方向没变就一直沿用最初那个。

建仓价      83,664 USDT    ← 2026-09-29 建立，已持有 6 天
当前浮动    价格 +2.51%　保证金口径 +7.54%（3×）
  • 价格 +2.51% = 现价 ÷ 建仓价 − 1（标的本身涨了多少）
  • 保证金口径 +7.54% = 价格变动 × 3（因为名义 = 保证金 × 3，

所以这笔保证金赚了 7.54%）

用途：一眼看出这一波拿了多久、现在赚还是亏。

方向没变的日子里，这行数字会随行情每天变，不用做任何操作。

邮件里的「止损提醒」要配置吗？——不用，它不会自动执行

结论：什么都不用配。 默认已经配好了（吊灯 5×ATR），你也不该照着它去手动砍仓。

三件事要分清：

是什么会自动执行吗
止损提醒（吊灯 5×ATR）一个参考价位：价格跌到这里，说明这波回撤已经很深了❌ 不会。脚本不挂单、不平仓，只是印在邮件上给你看
爆仓价交易所的硬底（3× 逐仓 = 建仓价 × 0.6717）✅ 会。价格到了币安强制平仓，只亏这个币的保证金
方向反转5 组 EMA 参数翻向 → 邮件告诉你「平仓 / 反手」✅ 会（如果你开了自动下单）。这才是策略真正的止损

为什么不该照着止损提醒去手动砍仓（回测实测）：

  • BTC 上挂吊灯 3×ATR 止损，会把 9 年 114.89× 打到 2.29× —— 砍掉的都是后来回本的大单
  • 最优止损距离跨资产不一致（SOL 上 0.64× → 0.16×），没法用一套参数通吃
  • 趋势策略的收益高度集中在少数几笔大单上，止损会精准地砍掉它们

所以这个提醒的定位是「极端行情保险」：真跌到那里，你至少知道发生了什么，

而不是被一个你根本不知道的价位打了个措手不及。

如果你还是想调（config.json → risk 段）：

"risk": {
  "stop_mode": "trail_atr",   ← none = 不显示止损位 | trail_atr = 吊灯移动止损 | fixed_pct = 固定百分比
  "trail_atr": 5.0,           ← 吊灯倍数。调小 = 止损更近、更容易被打到
  "fixed_stop_pct": 0.10,     ← stop_mode=fixed_pct 时生效，0.10 = 10%
  "take_profit_pct": 0.0,     ← 止盈位，0 = 不设（推荐，让利润奔跑）
  "liq_warn_pct": 0.10,       ← 距爆仓价 10% 以内时发「风控提醒」邮件
  "max_alerts_per_day": 3     ← 风控提醒每天最多几封，防刷屏
}

⚠️ **改这些只影响「邮件里印什么数字」和「什么时候发提醒邮件」，

不会改变策略的买卖行为。** 想让策略真的按价格止损，得改 trade.py 的逻辑 ——

但回测证据强烈不支持这么做。

为什么保证金不是固定值？

名义价值 = 权益 × 敞口        敞口 = min(3.0, 目标波动 ÷ 当日波动)
保证金   = 名义价值 ÷ 杠杆      ← 是「名义」÷ 杠杆，不是「本金」÷ 杠杆

保证金不是 1000÷3=334，它每天都在变。 B 档 9 年实测分布：

最小10 分位中位90 分位最大
10 U71 U201 U350 U565 U

变化来自两件事：① 波动率（波动大 → 自动缩仓）；② 5 组参数方向是否一致（不一致时互相抵消）。

所以每次邮件给的保证金就是这次该划的钱。 不用去记什么固定数字。

第 5 步：对接币安（★ 你要改的就这一处）

5.1 创建币安 API 密钥

登录币安 → 头像 → API 管理 → 创建 API → 选 系统生成

  • 权限：只勾 「允许合约」（Enable Futures）
  • 不要勾：提现（Withdraw）、划转（Transfer）
  • IP 白名单：稍后填（见 5.2）

创建后给你 API Key 和 Secret Key，Secret 只显示一次，先复制保存。

5.2 加 IP 白名单（★ 强烈建议）

币安 → API 管理 → 找到刚建的 Key → 编辑限制 → 限制访问 IP。

查你的公网 IP：

(Invoke-RestMethod "https://api.ipify.org?format=json").ip

为什么强烈建议：本程序为了兼容各种网络环境，

关闭了 HTTPS 证书校验（ssl.CERT_NONE）。

加了 IP 白名单，即使密钥被截获，别人也用不了。

注意：家庭宽带 IP 会变，变了要回来更新，否则下单报 -2015。

5.3 确认账户是「单向持仓」模式（★ 必做）

币安 App：合约 → 右上角设置 → 持仓模式 → 选「单向持仓」

本策略是单向净头寸（5 组参数合成一个方向）。

如果你账户是「双向持仓」，程序会直接拒绝运行并提示你改回来 ——

因为双向模式下同一交易对会有多空两条持仓记录，仓位会算错。

5.4 填进配置

编辑 config.json，找到 trade 段：

"apiKey": "在这里填你的币安API Key",
"apiSecret": "在这里填你的币安API Secret",

替换成真实密钥（保留引号）。

更安全的做法：不写文件，改用环境变量（程序优先读环境变量）

setx BINANCE_API_KEY "你的Key"
setx BINANCE_API_SECRET "你的Secret"

设完要重开命令行窗口才生效。

5.5 检查一个数字

"max_order_notional": 0

这是单次下单名义上限（防手滑/防配置写错）。

  • 填 0（推荐）：自动跟随账户规模 = 该币配额 × 3.15。

账户从 1000 U 涨到 5000 U 也不用手动改，永远不会悄悄卡住仓位。

  • 填正数：固定绝对上限。账户长大后它会变成「隐形的紧箍咒」 ——

比如填 3000，等账户涨到 1500 U 以上，理论仓位就会超过 3000，

此时每次调仓都会被这个上限削掉一截，而邮件里不会明显报错，属于静默缩仓。

四币模式下每个币的配额只有总权益的 1/4，更要留足空间。

一律填 0 就对了。

第 8 步：开启实盘

第一次只放 1000~5000 U 进合约账户，跑一两个月。

和「10 万本金只放 5 万进去」完全等价（本质是降档）。

8.2 打开开关

双击 run_switch.bat → 选 3 (ON) → 输入大写 YES 确认。

它会自动设置四个字段：

"trade": { "enabled": true, "dry_run": false }

8.3 真跑第一次

双击 run_trade.bat。它会：拉K线算信号 → 连币安读余额和持仓 →

算目标仓位并比对 → 有偏差就下单 → 发一封「已执行」邮件。

看到邮件里写着「已执行」就算成功了。

8.4 交给定时任务

不用再手动建任务 —— 第 2 步的 install_tasks.bat 已经把

BTC_Auto_Trade（每天 08:10）建好了，之前它一直空转，现在自动开始工作。

但建议先手动跑 1~2 周（每天双击 run_trade.bat），

确认每次动作都符合预期，再完全交给定时任务。

第 9 步：怎么停下来

  1. 一键关：双击 run_switch.bat → 选 2 (OFF)
  2. 手改：config.json 里 _master_switch.mode 改回 "observe"

关掉后会发生什么：

  • ✅ 邮件推送继续（不受影响）
  • ✅ 已开的仓位保持不动（程序不会帮你平仓）
  • ⛔ 不会再有新的下单动作

注意：关开关 ≠ 平仓。如果关闭时还有持仓，需要你自己决定继续持有还是手动平掉。

建议要么开着，要么手动全平 —— 别让它脱离策略管理。

必须知道的几件事

1. 会爆仓，但不会归零

3× 逐仓的爆仓距离是 -32.83%（= 1 − 1/3 + 0.5%），只跟杠杆有关，跟仓位大小无关。

9 年回测结果：A/B/C 三档各爆仓 1 次，都在 2018-01-16（BTC 单日 -33%）：

档期末权益最大回撤爆仓损失
A 保守10.00×-43.53%13.1 U
B 推荐19.40×-55.26%22.6 U
C 激进41.22×-71.13%47.2 U

逐仓只亏那一笔保证金，账户剩余资金不动 —— 那天三档各只掉 0.9% / 1.4% / 2.3% 的权益。

但要清楚最坏情况：保证金占权益的比例是会变的。

档中位90 分位历史最高
A13.7%22.7%33.6%
B19.8%32.9%52.3%
C30.8%52.1%94.3%

也就是说，B 档最坏情况爆仓会亏掉约一半本金，C 档接近归零。

之所以 9 年实际只亏 1.4%，是因为暴跌必然伴随高波动，而仓位是按波动率自动调的 ——

两者天然对冲。

2. 保证金占用是浮动的

见第 3 步的分布表。账户里要留够钱，否则会因为「可用保证金不足」下单失败（报 -2019）。

3. A / B / C 三档都在，随时可切

邮件推送：run_all.bat 一次推全部三档（合并一封），不用改配置。

想只看某一档，在文件夹里打开命令行（地址栏输 cmd）跑

strategy_a.py / strategy_b.py / strategy_c.py（需要 Python 在 PATH 里）。

自动下单：config.json → trade.profile，填 "A" / "B" / "C" 之一。默认 "B"。

只能填一个档位。 跑两个会互相覆盖仓位（都按账户总余额算）。

B 和 C 的相关系数是 0.99，同时跑两档等同于跑一个中间档。

每档参数都能改（三档互相独立）：

"profiles": {
  "A": { "vol_target": 0.02, "equity": 1000.0 },
  "B": { "vol_target": 0.03, "equity": 1000.0 },   ← 想调风险改这里
  "C": { "vol_target": 0.05, "equity": 1000.0 }
}

equity = 你投在这一档的本金，只影响邮件里显示的保证金/数量。

vol_target = 风险旋钮，想「比 B 激进、比 C 温和」就把 B 改成 0.035。

4. 权益口径（与回测一致）

下单时用的是币安实时余额（钱包余额 + 该仓位浮动盈亏），

和你 config.json 里填的 equity 无关 —— 那个只用于邮件显示。

目标名义 = (钱包余额 + 浮动盈亏) × 敞口

所以：你往合约账户里放多少钱，程序就按多少钱算仓位。

想「降档」就直接少放钱，不用改配置。

5. 幂等保护

同一天同一方向只会下单一次。程序中途崩了重启也不会重复下单。

看到日志说「幂等命中……跳过」是正常保护，不是故障。

6. 日志在哪

logs\ 目录。出任何问题，先看当天的日志。

文件内容
logs\live_ABC_日期.log信号推送日志
logs\trade_日期.log下单日志
logs\sync_check_日期.log对账日志
logs\alert_日期.log风控提醒日志

7. 只跑 BTC，还是四币合一（run_mode）

一个开关同时管住信号邮件和自动下单，就在 config.json 里：

"run_mode": "multi",     ← multi = 四币等权（BTC/ETH/BNB/SOL） | single = 只跑 BTC

"symbol":  "BTCUSDT",                                    ← single 用这个
"symbols": ["BTCUSDT","ETHUSDT","BNBUSDT","SOLUSDT"],    ← multi 用这些
仅 BTC（single）四币合一（multi）
每个币拿多少账户总权益全部账户总权益 ÷ 4
1000 U 本金，BTC 名义≈ 788 U≈ 296 U
单个币爆仓账户基本归零只亏那一个币的保证金，其余照跑
9 年实测17.7×分散后回撤更低，且动态再平衡 8/8 窗口全胜固定分配

想跑 3 个币：symbols 里删掉一个。想跑 5 个：加一个 "XRPUSDT"。

不用改别的任何地方。

临时切换（不改配置文件）：

run_trade.bat --single                      # 这次只跑 BTC
run_trade.bat --multi                       # 这次跑四币
run_trade.bat --symbols BTCUSDT,SOLUSDT     # 这次只跑这两个

邮件会同时给你两个视角（四币模式下）：

===== ① 四币等权 · 你实际要下的单 =====
  BTC  多  保证金  99 U  数量 0.003416  名义 296 U
  ETH  多  保证金  79 U  数量 0.087347  名义 238 U
  ...
  合计      保证金 328 U            名义 985 U
===== ② BTC 单跑参照（把 1,000 U 全押 BTC）=====
  BTC  多  保证金 263 U  数量 0.009109  名义 788 U
  ※ 这是对照，不要照着下单。

这样你能直接看出「分散」把 BTC 那份削掉了多少。

⚠️ 小额本金要注意「最小名义」：币安对每个交易对有 min_notional。

四币模式下 BTC 只分到 250 U，若门槛偏高，调仓会被拒。

跑一次 run_sync_check.bat，看第 6 段「交易精度参数（逐币）」就知道了。

现象处理
没收到邮件先查垃圾箱；再跑 run_all.bat --test；再看 logs\live_ABC_*.log
说「尚未配置密钥」回第 5.4 步填 config.json

报 -2015IP 变了，回第 5.2 步更新白名单
报「拒绝真实下单」开关没开全，双击 run_switch.bat 重新 ON
报「发现未完成的意图」上次下单可能中断。先跑 run_sync_check.bat 人工核对持仓，确认无误后加 --force
下单失败但邮件说失败立刻登录币安人工核对持仓，别重复跑
想确认到底下没下跑 run_status.bat，看持仓对照段

一句话总结

  1. 双击 run_all.bat → 收邮件（现在就可以开始）
  2. 双击 install_tasks.bat → 3 个定时任务全自动
  3. 观察 2 周以上，手动小额练手
  4. 对接币安：改 config.json 的 apiKey/apiSecret + 加 IP 白名单 + 账户设单向持仓
  5. 跑 run_sync_check.bat 确认连接 → run_trade.bat --dry-run 预演
  6. 小额入金 → run_switch.bat 选 ON → 开跑
  7. 想停就 run_switch.bat 选 OFF

全程只有一个开关需要你操心。其余交给脚本。

策略为量化研究结果，不构成投资建议。

实盘请从小资金起步，只用三年内不需要动用的闲钱。
