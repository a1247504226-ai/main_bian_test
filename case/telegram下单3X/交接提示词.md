## 0. 一句话背景

一套**币安 U 本位合约**的 Telegram 频道跟单机器人：监听 TG 频道信号 → 自动市价开仓 → 挂止盈止损 → 收到修正价位后改单 → TP1/TP2 到达移动止损 → 离场平仓。另有一套**回测/滚仓分析脚本**（同一工作区）和一份**100u 滚仓周报**：用户明确要求**从 2026-11-15 起算、起点之前的历史滚仓一律不算**，每周日 20:00 邮件推送。

> 保证金模式固定 **逐仓 ISOLATED**（每次开仓前 `set_margin_type` 强制设置，不是配置项）：
> 单仓爆仓最多亏掉该仓保证金，不牵连其他仓位。已有持仓/挂单时币安不允许改，

### 两阶段保护机制（核心设计）
1. **开仓**：市价开仓成功后，立即挂**兜底**止盈 7% / 止损 5%（`closePosition=true` 全平）。
2. **改单**：频道随后发来真实 `止盈：xxx 止损：xxx` → `amend_protection()` 撤旧单挂新单，并写 `pending`（status=protected，保存 tp_all 全部目标价）。
3. **移损**：TP1 到达 → 止损移到 TP1 外侧 0.5%；TP2 到达 → 移到 TP2 外侧。
4. **离场**：频道发「离场」→ 撤单 + 市价平仓，用平仓前后余额差算真实盈亏。

## 4. 已修 Bug 清单（★别回退，都是实盘会踩的坑）

1. **单向/双向持仓模式**：旧代码无条件带 `positionSide`，单向账户下止损单报 `-4061` → 开仓后立刻紧急平仓。现启动探测 `GET /fapi/v1/positionSide/dual`（只查 1 次），单向不带 positionSide + 用 reduceOnly，双向必须带 positionSide 且不能 reduceOnly；遇 -4061 自动翻转重试。
2. **止盈挂不上也紧急平仓**：止盈和止损曾同一 try，止盈失败会平掉刚开的仓。现分开：止损失败才紧急平仓，止盈失败保留仓位+告警。
3. **平仓前撤单失败阻止平仓**：`cancel_all` 抛错会整个 close 失败。现撤单失败也继续平仓。
4. **改单幂等单号只到秒**：同秒两次改单撞 `-4116`。现毫秒精度 `int(time.time()*1000)%10**10`。
5. **止损价取整方向错**：曾永远 ROUND_DOWN，空单止损向下取整会靠近入场价被提前扫。现 SELL 向下、BUY 向上（止损远离入场，止盈靠近）。
6. **开仓前不清理历史挂单（幽灵单）**：上笔仓的止盈单残留，新仓一开被老单平掉。现开仓前先 `cancel_all`，清不掉就拒绝开仓。
7. **无币种止盈止损错配**：频道 TPSL 消息不带币种。现按**价位反推**归属，只有唯一合理候选才采用；两仓价格接近则拒绝猜。
8. **开仓自带保护不写 pending**：自带 TP/SL 的开仓消息曾不写 pending，导致后续改单/移损/巡检全失效。现补写 status=protected + tp_all。
9. **空闲也在连币安**（用户明确要求「有信号才连」）：① 去掉启动主动 `_sync_time()`，改懒同步（第一次签名请求才校准）；② 启动查持仓默认关；③ 巡检事件驱动（有仓位才查，5 分钟一次）；④ serve 的 60s ping 改 `health_ping_interval`（默认 0）。连接类日志同类 60s 最多一条。
10. **CLI 幂等单号撞号**：手动 `open`/`batch` 不带 `--id` 时 `signal_id` 空，同币同方向每次同 coid → 第二笔被 -4116。现 `Signal.__post_init__` 自动生成 `auto-<毫秒>-<随机>` 唯一 id；显式给 id 仍幂等。
11. **main.build() 启动主动连币安**：已删，统一懒同步。
12. **邮件中文主机名 bug**：本机主机名含中文（"电教室4-3"），smtplib 的 EHLO 按 ascii 编码崩 → 所有邮件发不出。修复：`SMTP_SSL(..., local_hostname="localhost")`（mailer.py 和 weekly_report.py 都已修）。
13. **系统代理导致 418**（★「日志总提示币安链接问题」真凶）：Windows 系统代理 `127.0.0.1:7897` 出口 IP 被币安封，requests 默认走系统代理 → 签名接口全 418，公开接口 200（误导）。修复：`BinanceFutures` 的 session 设 `trust_env=False` 直连；需要代理时设 `BINANCE_PROXY` 环境变量。
14. **条件单迁到 Algo Order API**（2026-11 币安变更）：STOP_MARKET/TAKE_PROFIT_MARKET 在 `/fapi/v1/order` 报 `-4120 Order type not supported`。现改用 `POST /fapi/v1/algoOrder` + `algotype=CONDITIONAL` + `triggerPrice`（不是 stopPrice）+ `clientAlgoId`（幂等）；查询 `GET /fapi/v1/openAlgoOrders`；撤单无批量接口，逐个 `DELETE /fapi/v1/algoOrder?algoId=`。`cancel_all` 同时撤普通单+algo 单，`get_open_orders` 合并两者。
15. **开仓自带多档止盈只存 TP3**（2026-11-16 查出）：`signal_parser` 开仓分支只设 `ev.tp = nums[-1]`，`tp_all` 为空 → executor 写 pending 时 `tp_all` 只有兜底价，TP1 到达时按兜底价移损，止损价位/方向都会错。现补 `ev.tp_all = nums`。实测 3413 条历史消息：383 个开仓信号里 **24 个带 2~3 档止盈**，全部受益。
16. **空格分隔的多档止盈解析不到**（同上）：`TP_RE` 只认 `-` 分隔，`止盈：70000 71000 72000` 只取第一个。现字符类加**行内空格**（不能用 `\s`，会跨行把下一行止损价吃进来），`_parse_num_list` 同步按 `[-\s]+` 切分。
17. **小价格币参数变科学计数法**：`urlencode` 对 float 用 `str()`，`1.2e-05` 会被币安判非法（保护单挂不上 = 裸仓）。现 `_request` 统一把 float 用 `Decimal` 转定点字符串（`0.000012`）。
18. **重试沿用旧时间戳**：429 等 30~120 秒后仍用循环外算的 `timestamp` → 必然 -1021。现每次重试重算。
19. **保护单被权重预算卡 65 秒**：`_w_wait` 最多等 65 秒，开仓后挂止损可能裸仓 65 秒。现 `urgent=True` 最多等 5 秒，条件单/撤单/查 algo 全走 urgent。
20. **openAlgoOrders 返回结构假设**：只按 list 遍历，若被包成 dict 会崩。现 `_algo_list()` 兼容 `orders/rows/data`。
21. **新上币种精度缓存不刷新**：`_info_loaded` 一次置位后，`get_filters` 对新币种直接抛「不存在」。现 60 秒节流强制重载 exchangeInfo。
22. **Telegram session 被作废直接抛栈**（2026-11-16 实盘遇到）：日志报
    `AuthKeyDuplicatedError: The authorization key was used under two different IP addresses simultaneously`。
    根因是同一份 `.session` 被两台机器/两个进程同时使用，或代理节点切换导致出口 IP 变化；
    Telegram 会**永久作废**这个 auth key，旧文件不能复用。现在：
    ① `tg_listener.py` 捕获所有 AuthKey/Session 类错误 → `SessionInvalidError`，附带中文修复步骤；
    ② `trader.run_live` 捕获后打印清晰指引并 `exit(2)`，不再抛长栈；
    ③ 新增 `tg_login.py` 重新登录（手机号 → 验证码 → 2FA），旧 session 自动改名 `.bak` 不删除。
    纪律：同一 session 只能一台机器跑；两台机器各登录一次、用不同 `TG_SESSION`；代理节点固定。
23. **改单撤旧单后新止损挂不上 → 裸仓**（2026-11-16 查出）：`amend_protection` 撤完旧单直接
    `stop_loss`，抛异常就一路冒泡，旧单已撤、新单没挂，仓位裸奔且不会重试。现加回滚：
    用 pending 里的旧止损价重挂；回滚也失败 → `_emergency_close` 立即市价平仓并告警。
24. **改单异常不重试**：`_handle_tpsl` 调 amend 抛异常时，TPSL 数据已从 buf 删除，永久丢失，
    仓位一直停在旧保护。现捕获异常并 `buf.restore()` 放回重试队列；TP_HIT 移损异常同样处理。
25. **撤单确认查询失败被误判成「旧单还在」**：原来直接 return「放弃改单，当前仍是旧保护单」，
    但查询失败 ≠ 旧单还在，实际可能已撤干净 → 裸仓。现区分「查询成功且还有单」（安全放弃）
    和「查询失败」（继续挂新止损兜底）。
26. **`get_open_orders` 吞 algo 查询异常**：撤单确认会把「查不到」当成「已清空」。
    现加 `strict=True`，改单确认和开仓前复核都用严格模式。
27. **止盈挂失败时清空 `tp_all`**：之后 TP1/TP2 到达会被「目标价不全」忽略，止损永远不提。
    现保留 `tp_all`，只把 `tp` 置空（表示当前没有 TP 挂单）。
28. **开仓前 `cancel_all` 失败被吞**：`cancel_all` 内部把单次撤单失败吞成 warning，
    外层「清不掉就拒绝开仓」形同虚设。现在撤完用 `get_open_orders(strict=True)` 复核，
    仍有挂单就拒绝开仓。改单单号也加了随机后缀，避免同毫秒撞 -4116。
29. **关键失败只发 TG、不发邮件**（2026-11-16 用户要求「失败了就推送邮件」）：
    保护单失败、改单/回滚失败、平仓 0 成交/剩余仓位/持仓查询接口报错、撤单未确认、TP 移损异常、
    改单连续失败等，以前只有 `_alert`（日志+TG），无人值守容易漏。现统一 `_critical()`：
    `log.error` + TG + 邮件（主题「【交易机器人告警】」），**同类 60 秒限流**，dry-run/回放不发。
    开仓失败（没仓位、不会亏钱）仍只走 `_alert`，不刷邮件。
30. **保证金下调用估算值导致 -2019 拒单**（2026-11-17 测试网实跑查出）：账户有其它仓位/挂单锁保证金时，
    `open()` 原来用 `avail = 权益 - 估算占用` 下调新仓保证金。实测估算 1325.41U vs 币安真实
    `availableBalance` 1324.83U，按估算下调后仍超 0.58U → 币安 `-2019 Margin is insufficient` 直接拒单
    （主网同样会踩）。现改为**优先用币安返回的真实 `available`**，再乘 0.99 安全垫；
    dry-run 仍用「权益-估算占用」以便验证虚拟多仓。日志会打印币安真实可用值。
31. **TP1 移损不校验现价，误报时白撤单+回滚**（2026-11-17 完整链路实跑查出）：
    `_handle_tp_hit` 原来算出 `new_sl = 目标×1.005` 直接调 relax 改单。频道误报 TP1（价格还没到目标）
    或价格反弹穿越移损位时，新止损落在现价错误一侧，币安 `-2021 Order would immediately trigger`，
    amend 已撤旧单→回滚→白烧权重且留裸仓窗口。现加**现价预检**：新止损在错误一侧则跳过移损、
    保留当前止损并告警（`key=trail_side_*`）；取现价失败也跳过。dry-run/回放跳过此检查，不误伤统计。
    实测：误报 TP1 从 `fail=1`（撤单+回滚）变成 `skip=1`（零撤单）；正常移损（新止损在正确一侧）
    仍 `ok=True` 挂单成功。
32. **风控总保证金口径不一致，误拒开仓**（2026-11-17 split 链路实跑查出）：bug 30 只改了
    `executor` 下调口径（用真实 available），但 `risk.check_open` 的总保证金校验仍用
    `equity - 估算占用`。全仓 BTC 单两者差几十 U → 出现「executor 已按真实可用下调、
    风控仍判总占用 100.3% > 100%」的误拒（真实可用其实够）。修复：`check_open` 加可选
    `available` 参数，executor 传入真实 `availableBalance`；有值时用 `equity - available`
    反推已占用，与 executor 口径统一；dry-run 无 available 时回退估算（不影响回放）。
    实测修复前开仓被拒，修复后同场景开仓成功。
33. **失败的开仓信号顶掉止盈止损归属**（2026-11-17 从 `logs/trader.log` 历史记录查出，
